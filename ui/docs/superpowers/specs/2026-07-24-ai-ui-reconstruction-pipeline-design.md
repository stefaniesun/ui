# AI 高保真跨端 UI 还原流水线设计

## 1. 背景与目标

建立一套长期可复用的 UI 生产流水线。开发者手工整理主流 App 的参考截图，本地多模态模型负责视觉理解、代码生成、自动渲染、差异诊断和循环优化，最终由人工完成视觉评审。

首要交付端为微信小程序和 iOS/Android App，一套代码实现。技术栈采用 Vue 3、TypeScript 和成熟版 uni-app；H5 用于快速视觉迭代，微信小程序作为首个正式验收端，Android/iOS 在后续阶段加入自动兼容验收。首版不直接押注 uni-app x。

目标不是一次生成完整页面，而是形成可观测、可回退的自主收敛闭环：

`素材输入 → 视觉测量与理解 → Visual IR → 代码生成 → 固定环境渲染 → 多指标测量 → 差异诊断 → 定向补丁 → 回归验证 → 人工评审`

首版完成一个页面的多状态闭环，包括默认、加载、空态和弹窗等关联状态；数据结构和接口为完整页面流程预留扩展能力。

## 2. 设计原则

1. 截图不直接变成一次性页面代码，必须经过可校验的 Visual IR。
2. 工具测量事实与模型推断分离。推断项携带置信度和来源。
3. 静态视觉强约束还原，潜在交互和动画按置信度处理。
4. 所有图标和业务图片进入可替换资产槽位，不与页面代码绑定。
5. AI 按语义区域定向修改，禁止每轮重写整页。
6. 视觉分数和代码健康性同时作为质量门禁。
7. H5 负责快速收敛，微信小程序结果优先于 H5；端差异通过适配层解决。
8. 每轮结果必须可追溯、可比较、可回退。
9. 本地模型通过 OpenAI 兼容接口接入，不依赖固定厂商。
10. 首版建设 IDE Agent 与 CLI 核心，不提前建设 Web 平台。

## 3. 范围

### 3.1 首版包含

- 人工整理的参考截图、资产和 `manifest.yaml`。
- 单页面多个关联状态。
- 字体、颜色、排版、间距、几何、图标和图片资产分析。
- 语义区域自动拆分、自定义名称/别名和组件双向映射。
- Visual IR、项目级基础 Design Token 和必要公共组件。
- OpenAI 兼容本地多模态模型适配器及能力自动探测。
- H5 快速视觉迭代和微信小程序正式视觉验收。
- 结构、几何、颜色、OCR、区域 SSIM 和感知复审的组合评分。
- 最多八轮 AI 自主优化、停滞检测、自动回退和人工评审报告。
- 图标及图片资产的语义键、替换接口和替换后视觉回归。
- 类型、静态规则、组件契约和视觉回归等代码健康门禁。

### 3.2 后续扩展

- 自动识别完整业务流程、页面关系和路由。
- Android/iOS 模拟器或真机自动验收。
- 录屏驱动的动画时序分析。
- 团队级设计资产和公共组件知识库。
- Web 上传平台、任务队列、团队评审和权限管理。

### 3.3 非目标

- 不自动抓取需要登录或受使用条款限制的网站素材。
- 不承诺仅凭单张截图精确还原复杂动画、地图、3D、视频或系统原生控件。
- 不通过整张背景图、大量绝对定位或一次性 CSS 获取虚假相似度。
- 不在缺少证据时把推断交互标记为截图事实。
- 参考截图（如 uinotes 等来源）仅用于内部还原与验收。上线前所有品牌图标、插画、徽标等第三方资产必须通过资产槽位替换为自有素材；该检查作为人工评审报告的固定检查项。

## 4. 总体架构

采用 Monorepo，核心模块如下：

- `apps/reference-app`：Vue 3、TypeScript、uni-app 页面、路由、状态夹具和多端构建入口。
- `packages/visual-ir`：Visual IR 类型、JSON Schema、版本迁移、置信度和来源标记。
- `packages/design-system`：Design Token、通用组件、图标/图片资产注册表和端差异适配。
- `packages/model-adapter`：OpenAI 兼容 API、能力探测、结构化输出、重试和本地地址约束。
- `packages/visual-engine`：截图、OCR、几何测量、颜色差异、SSIM、热力图和区域评分。
- `packages/orchestrator`：任务状态机、诊断、补丁计划、回归、停滞检测和回退。
- `packages/cli`：环境检查、项目初始化、分析、运行和评审入口。
- `packages/report`：区域标注、对比图、指标、变更记录和人工反馈界面。

CLI 是稳定核心。IDE Agent 通过 CLI 完成任务理解、执行、修正和总结；未来 Web 平台复用同一核心能力。

## 5. 输入素材规范

每个页面使用独立素材包：

```text
pages/profile/
  manifest.yaml
  reference/
    default.png
    loading.png
    empty.png
    dialog-open.png
  assets/
    icons/
    images/
    fonts/
```

`manifest.yaml` 至少包含：

- 项目、页面和状态 ID。
- 截图路径及页面状态关系。
- 设备宽高、像素比、安全区和系统栏策略。
- 每张截图的 `screenshotType`（`viewport` 视口截图或 `fullpage` 滚动长截图）和 `scale`（物理像素与逻辑像素倍率，如 iPhone 3x）。
- 固定测试数据及进入状态的操作步骤。
- 动态内容遮罩和可忽略区域。
- 关键区域及其最低评分。
- 人工提供的交互说明。
- 自定义资产映射。
- 允许复用的组件与禁止修改的业务约束。

首版由人工下载和整理截图。若附加多状态截图、合法图片素材、图标、字体、交互说明或短录屏，系统使用这些信息提升确定性；缺失信息不阻塞静态还原，但会降低相关推断的置信度。

### 5.1 参考截图预处理

`analyze` 的第一步对参考截图做归一化，之后所有测量和评分都基于归一化结果：

1. 按 `scale` 将物理像素归一到逻辑像素（uinotes 等来源多为 iPhone 2x/3x 物理分辨率）。
2. 按 manifest 系统栏策略裁剪状态栏区域，或将其标记为不计分遮罩。
3. 区分 `viewport` 与 `fullpage` 截图：长截图对应渲染器的 fullPage 截图模式，两侧必须使用同一模式才可比。
4. 校验归一化后尺寸与 manifest 设备宽度一致，不一致时报错而不是静默缩放。

## 6. Visual IR

Visual IR 是截图理解、代码生成、视觉验收和人工沟通之间的稳定合同。

### 6.1 核心对象

- `ProjectProfile`：色板、字体阶梯、间距、圆角、描边、阴影和图标风格。
- `PageSpec`：页面区域、滚动容器、导航、层级和组件树。
- `StateSpec`：默认、加载、空态、弹窗等状态及触发条件。
- `RegionNode`：语义区域树节点。
- `RegionConstraint`：边界框、对齐、文字、素材、关键级别和容差。
- `AssetSlot`：可替换图标、图片、徽标和字体。
- `InteractionHypothesis`：潜在交互、动画和置信度。

### 6.2 事实与推断

OCR 文案、图像边界、颜色采样和几何尺寸属于工具测量事实。组件语义、区域名称、页面关系和潜在交互属于模型推断。每项信息记录：

- `source`：工具、模型或人工。
- `confidence`：0 到 1。
- `evidence`：截图区域或人工说明。
- `override`：人工是否已覆盖。

人工覆盖的信息优先级最高，后续模型不得自行覆盖。

参考图侧的全部工具测量（OCR 文字与边界、颜色采样、几何尺寸）在 ANALYZE 阶段执行一次并冻结进 Visual IR。后续所有迭代轮次针对这份冻结目标收敛，不重复测量参考图，避免测量漂移导致评分震荡和停滞误判。

## 7. 语义区域与代码映射

### 7.1 自动区域拆分

区域候选由以下证据共同产生：

- 背景变化、卡片边界、留白、分割线和对齐线。
- OCR 文案、标题与内容关系、图标语义和业务词组。
- 重复尺寸、等分列、共同基线和网格规律。
- 点击单元、独立状态和潜在复用边界。

工具产生边界候选，模型负责合并、拆分和语义命名。

首版（MVP）阶段不实现工具侧边界检测：多模态模型给出的区域边界仅作候选（本地视觉模型的坐标定位精度普遍不足），评分裁切以人工 `region-overrides` 提供的边界为准。工具侧边界候选生成在阶段二加入。

以个人中心页面为例，区域树可包含：

- `account-summary`：账号概览区。
- `creator-actions`：创作与消息区。
- `publish-prompt`：首篇内容发布区。
- `points-overview`：积分概览区。
- `personal-tools`：个人工具区。
- `owner-services`：车主服务区。
- `primary-tabbar`：一级底部导航。

### 7.2 名称与别名

每个 `RegionNode` 包含：

- `regionId`：稳定机器标识，不随显示文案变化。
- `displayName`：AI 生成或人工修改的名称。
- `aliases`：人工添加的沟通别名。
- `bounds`：参考图和实现图中的边界框。
- `parentId/children`：父子关系。
- `confidence`：区域识别置信度。
- `componentPath`：绑定组件。
- `selector`：运行时定位方式。

人工可使用“车主服务区 / `service-grid` 第二行图标间距缩小 4px”一类指令。系统据此限制 AI 修改范围并执行整页回归。

### 7.3 组件拆分原则

区域树与组件树可追踪，但不机械地一块一组件。只有满足独立语义、独立状态、重复出现、可复用或需要独立调整之一时才提取组件。纯装饰节点保留在所属区块。

代码分层：

- 页面编排层只负责区域顺序、页面状态、数据装配和路由事件。
- 业务区块层承载账号概览、功能宫格、积分概览和车主服务等区域。
- 通用组件层承载卡片、图标操作项、模块标题和徽标。
- 设计资产层承载 Token、字体、图标注册表和端差异变量。

## 8. 静态视觉还原

### 8.1 坐标与布局

首先识别系统状态栏、页面内容、固定底部导航、安全区和滚动边界。关键区域保存 `x/y/w/h` 和容差。布局优先使用 Flex、Grid、正常文档流和统一间距 Token，禁止以大量绝对定位模拟截图。

单位换算统一约定：Visual IR 中所有 bounds 和几何测量使用参考图**逻辑像素**；代码生成按 `750 / 设备逻辑宽度` 换算为 uni-app rpx 写入样式和 Token；评分时将渲染截图测量值反向换算回逻辑像素比较。任何环节不得混用物理像素。

### 8.2 OCR 与字体

#### 混合 OCR 策略

避免同源测量偏差：若同一个多模态模型既读参考图又读实现图，其系统性识别错误在两侧抵消，文案错误不可见，且模型输出的边界框精度和逐次一致性都不足以做像素级测量。因此 OCR 分两路：

- **测量事实**：本地确定性 OCR 引擎（首选 PaddleOCR）提供文字内容和像素级边界框。同图同结果，免费、快，承担每轮迭代的高频测量。
- **语义理解**：多模态模型（本地或中转站接入）负责区域命名、组件语义、图标含义和差异诊断，不承担几何测量。
- **交叉校验**：两路文字识别不一致的条目进入人工确认清单；两个独立传感器的分歧正是暴露系统性误差的机会。

多模态模型不得作为文案匹配率门禁的唯一测量来源。

#### 字体流程

1. 本地 OCR 获取文字、边界框和行结构。
2. 根据像素高度估算字号、行高和字重。
3. 聚类为项目级字体阶梯。
4. 使用目标端真实字体渲染。
5. 比较文字边界、基线、换行和截断。
6. AI 调整字号、字重、行高和字间距并重新验证。

参考截图多为 iOS PingFang SC 渲染，而开发机（Windows）浏览器默认中文字体和抗锯齿方式完全不同，会造成系统性字宽、行高偏差。H5 测量层内置一款开源中文字体（如 MiSans、HarmonyOS Sans 或 Noto Sans SC）作为统一测量基线，通过 `@font-face` 强制加载，字体维度评分容差按该基线校准。H5 与微信小程序字体渲染可能不同，正式端结果优先；必要时使用端差异字体 Token。

### 8.3 颜色

从纯色区域聚类背景、卡片、主文字、次文字、强调色和状态色。采样避开字体抗锯齿、压缩噪点和图片内容。颜色差异使用 Lab 与 ΔE 评估，而不是只比较 RGB。

### 8.4 间距和几何

利用卡片边界、重复元素中心线和等距网格归纳页面边距、卡片内边距、列间距、行间距和图标基线。AI 优先修复骨架和大尺寸误差，再处理 1 至 4 像素的局部误差。

## 9. 图标和图片资产

资产自动分为：

- 线性 UI 图标。
- 品牌或业务插画。
- 头像和内容图片。
- 文字徽标及状态标签。

每个资产使用语义键，如 `icon.notice`、`tab.home`、`service.refuel`，并记录：

- 资产类型和候选来源。
- 参考裁切框和视觉尺寸。
- 颜色、基线、裁切方式和置信度。
- 替换文件路径。

系统可以匹配统一 SVG 图标集或生成近似占位资产。人工可通过替换文件或修改 manifest 映射修正图标。资产槽位维持固定布局合同，替换后自动重跑视觉回归，检查尺寸、视觉中心和周围间距。

## 10. 交互与动画推断

单张截图只能证明状态，不能证明时间过程。系统将交互分级：

- 高置信度：登录入口、发布按钮、功能入口、底部 Tab 切换等平台常见语义，可默认实现标准交互。
- 中置信度：车型选择可能是页面或底部弹层，采用可配置实现并列入评审。
- 低置信度：横滑、复杂弹簧、共享元素、骨架屏动画等，不凭空实现。

默认微交互限于按压透明度、轻微缩放、标准路由转场和选中态切换。复杂动效需多状态截图、录屏或人工说明。每个 `InteractionHypothesis` 记录触发元素、前后状态、推荐实现、证据和置信度。

## 11. 本地模型适配器

模型通过 OpenAI 兼容 API 接入，配置包括：

- `baseURL`、`apiKey`、`model`。
- 图片传输方式、超时、重试、并发和上下文限制。
- 仅本地/可信地址访问策略。远程中转站地址必须在 manifest 白名单中明确声明才允许使用；使用中转站意味着参考截图会离开本地，manifest 中该声明同时作为知情确认。

调用频率约定：高频测量（OCR、颜色、几何、像素差异）全部由本地确定性工具承担；模型仅在 ANALYZE、DIAGNOSE 和 REVIEW 阶段调用，控制 8 轮迭代的 API 成本和延迟。

`ui-rebuild doctor` 依次探测：

1. 图片输入及尺寸限制，并检查模型最大输入分辨率是否覆盖参考截图尺寸；超限时提示分块或降低预期，不接受静默降采样（长图被模型自动降采样后，字号和间距测量不可信）。
2. `response_format/json_schema`。
3. 工具调用。
4. JSON Mode。
5. 提示词约束 JSON。

系统缓存能力档案并选择最稳定模式。所有模型输出经过 Schema 校验；失败时执行格式修复、重试或降级。统一接口：

- `analyzeScreens()`：生成或修订 Visual IR。
- `diagnoseDiff()`：将客观指标和热力图转为修复任务。
- `reviewResult()`：执行最终视觉复审并生成建议。

模型不直接给自己打最终分，客观工具指标是质量门禁主体。

## 12. AI 自主迭代状态机

状态流：

`INGEST → ANALYZE → GENERATE → RENDER → MEASURE → DIAGNOSE → PATCH → REGRESSION`

未达门禁时进入下一轮。一次只解决一个问题簇，优先级为：

`骨架 → 字体 → 间距 → 颜色 → 图标/图片 → 微细节 → 交互状态`

`PatchPlan` 必须指定：

- 目标区域和根因。
- 允许修改的文件、组件和 Token。
- 预期改善指标。
- 可能受影响的关联状态和端。
- 回退条件。

补丁仅在以下条件同时满足时接受：

- 目标区域得分提升。
- 整页得分未显著下降。
- 其他状态未产生新严重缺陷。
- H5 改善未破坏微信小程序结果。
- 类型、静态规则和组件契约通过。

否则恢复上一稳定快照。

停止条件：

- 成功：综合得分和关键区域门禁全部通过。
- 停滞：连续两轮提升低于 0.5%。
- 上限：默认达到八轮。
- 异常：模型、渲染器或端差异无法自动恢复。

停止后始终保留最佳轮次，不以最后一轮覆盖最佳结果。

## 13. 质量评分与 80%–90% 目标

“80%–90%”定义为工程加权质量分，不等同于严格的全图像素一致率。建议权重：

- 骨架与几何：30%。
- 字体、颜色、间距、圆角和阴影：30%。
- OCR 文案、图片裁切和图标语义：15%。
- 公共组件与 Design Token 一致性：15%。
- 页面状态及交互结果：10%。

自动提交人工评审的门禁：

- 综合加权得分不低于 0.88。
- 每个关键区域不低于 0.85。
- 关键元素几何平均误差不高于 4px。
- OCR 文案匹配率不低于 98%。
- 严重视觉缺陷为 0。
- 公共 Token 一致性为 100%。

本地 OCR 引擎不可用时，content 维度置 null 并按剩余权重归一化，不记 0 分；同时 doctor 给出明确诊断，评审报告标注"文案未验证"，不允许在无 OCR 的情况下伪报文案匹配通过。

典型收敛预期：

- 初稿：55%–70%。
- 第 1–2 轮：70%–80%。
- 第 3–5 轮：80%–88%。
- 第 6–8 轮：88%–92%，边际收益下降。

该预期适用于截图清晰、设备明确、素材可获得、状态相对完整的常规列表、详情、表单和弹层页面。复杂动画、地图、3D、视频和重度原生控件需要人工补充材料或降低预期。

## 14. 代码健康性门禁

视觉相似不能以牺牲代码质量为代价。每轮补丁必须通过：

- TypeScript 类型检查。
- 静态代码和样式规则。
- 组件单一职责及 Props/Events 契约检查。
- 重复模板和重复样式检测。
- Design Token 使用检查。
- 业务状态与展示结构分离检查。
- 区域 ID、Visual IR、组件路径和评审报告的双向定位检查。
- 组件测试、状态回归和视觉回归。

自动拒绝：

- 整页绝对定位。
- 截图作为整张页面背景。
- 大量内联魔法数字。
- 重复复制宫格模板而非数据驱动。
- 单文件持续膨胀且职责混杂。
- 为单张截图硬编码动态数据。
- 为提高局部分数破坏公共组件契约。

## 15. 渲染与验收层级

### 15.1 H5 快速层

用于秒级热更新和多数布局、字体、颜色、间距迭代。截图确定性的承诺范围是**同机器可复现**（固定 viewport、字体、fixture、禁用动画），不承诺跨机器逐像素一致（ClearType 等系统级渲染差异无法消除）。

### 15.2 微信小程序正式层

处理字体、单位、样式隔离、导航、安全区和组件行为差异。微信小程序是正式质量门禁端，但其自动化落地节奏如下：

- **MVP 阶段**：质量门禁仅以 H5 为准；`--target wechat` 明确报"尚未支持"，不静默回退到 H5。
- **后续计划**：接入微信开发者工具自动化。前提条件需写入 doctor 检测：开发者工具已安装、设置中已开启服务端口（CLI/HTTP）、工具处于登录态，通过 `miniprogram-automator` 驱动。全部就绪后微信小程序分数取代 H5 成为通过依据。

### 15.3 Android/iOS 兼容层

后续通过模拟器、真机、ADB、Appium 或 Maestro 检查安全区、键盘、滚动、原生能力和系统字体差异。端差异进入专用 Token 或适配组件，禁止污染公共布局逻辑。

## 16. 异常与降级

- 模型不支持 Schema：依次降级到工具调用、JSON Mode 和提示词 JSON，并执行本地 Schema 校验与修复。
- OCR 或图标识别低置信度：保留候选与资产槽位，进入人工确认清单。
- H5 与微信小程序冲突：正式端优先，通过端差异 Token 或适配层解决。
- 动态数据引发无效差异：使用固定夹具或遮罩。
- 两轮无明显改善：停止循环并保留最佳轮次。
- 替换素材改变布局：恢复资产槽位约束并重新评估视觉中心。
- 本地模型不可用：保存任务状态，允许恢复，不在未知模型上自动切换。

## 17. 可追溯产物与人工评审

每一轮持久化：

- Visual IR 版本。
- 代码补丁和影响范围。
- H5、微信小程序及后续 App 截图。
- 参考图、实现图和差异热力图。
- 整页和各语义区域评分。
- 模型输入摘要、结构化输出、重试和回退记录。
- 稳定快照和最佳轮次。

人工评审报告显示带名称的区域框。点击区域可查看：

- `regionId`、显示名称和别名。
- 参考图和实现图裁切对比。
- 字体、颜色、几何、OCR 和 SSIM 指标。
- 绑定组件、Token 和资产槽位。
- AI 已执行的修改。
- 未解决问题、推断交互及置信度。

人工可修改区域名称、添加别名、替换资产或提交区域级意见。反馈重新进入同一迭代闭环，AI 只修改指定区域并执行整页和关联状态回归。

## 19. CLI 使用体验

```text
ui-rebuild doctor
ui-rebuild init <page>
ui-rebuild analyze <page>
ui-rebuild run <page> --target h5,wechat --max-rounds 8
ui-rebuild review <page>
```

- `doctor`：探测本地模型、Node、H5 浏览器和微信开发者工具环境。
- `init`：创建素材包、manifest 和区域命名覆盖文件。
- `analyze`：生成 Visual IR、语义区域树、Token 和资产候选。
- `run`：生成页面并执行自主迭代。
- `review`：打开区域化人工评审报告并接收反馈。

## 20. 分期计划

### 阶段一：可验证的单页面多状态闭环

## 21. 验收标准

首版完成的判定条件：

1. 可输入一个页面至少两个关联状态并生成有效 Visual IR。
2. 可自动生成带语义区域标识的可运行 uni-app 页面。
3. 区域显示名称、别名和组件路径可双向定位。
4. 图标和图片可通过语义键替换且无需修改页面结构。
5. H5 与微信小程序至少完成一次真实自动渲染和截图。
6. AI 可依据客观差异完成至少三轮定向修改，并在退化时回退。
7. 可按 0.88 综合门禁自动提交人工评审，或在停滞时输出瓶颈报告。
8. 最终报告可按区域提交反馈，并触发限定范围的再次迭代。
9. 生成代码通过类型、静态规则、组件契约和视觉回归。
10. 不使用整图背景、大量绝对定位或不可维护的复制代码实现相似度。
