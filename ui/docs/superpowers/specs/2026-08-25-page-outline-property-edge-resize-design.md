# 整页轮廓属性栏右边缘调宽设计

2026-08-25 · 分支 `dev`

## 1. 背景与目标

整页轮廓当前支持两条内部可拖动分隔线：原图与结构树之间、结构树与属性栏之间。内部分隔线只重新分配相邻两栏宽度，因此舞台总宽保持不变。属性栏最右边缘目前不能拖动，用户无法在不压缩结构树的前提下单独扩大属性编辑区域。

本次目标：

1. 属性栏最右边缘支持拖动调宽。
2. 拖动只改变属性栏宽度，不改变原图和结构树宽度。
3. 舞台总宽随属性栏宽度同步增减。
4. 展开和收起结构树时均可使用。
5. 保持无限画布缩放、平移、适应视图及现有两条内部分隔线行为。

## 2. 已选方案

采用覆盖式右边缘拖动柄。

拖动柄覆盖在属性栏右边缘内侧，不新增 Grid 列、不占据额外布局宽度。它复用现有 Pointer Events 调宽会话、缩放换算、指针捕获和清理机制。

选择理由：

- 只改变属性栏宽度，符合“调整最后一块区域”的直接语义。
- 不改变默认 Grid 结构和当前 `1200px`展开态舞台宽度。
- 无需增加第三个固定分隔列或修改分隔线宽度计数。
- 展开与收起结构树时可以使用同一个右边缘拖动柄。

不采用：

- 第三条 Grid 分隔列：会额外占用宽度并改变默认舞台尺寸。
- 直接使用单像素边框：命中范围过窄，拖动体验不稳定。
- 调宽时挤压结构树或左侧两栏：与“单独扩大最后区域”的目标不符，并与现有内部分隔线职责重叠。

## 3. 布局和宽度规则

属性栏右边缘拖动属于“外边缘调整”，与现有内部边界不同：

- `image-tree`：原图与结构树此消彼长，舞台总宽不变。
- `tree-property`：结构树与属性栏此消彼长，舞台总宽不变。
- `property-edge`：只改变属性栏宽度，舞台总宽同步变化。

计算规则：

```text
property = max(220px, dragStartProperty + stageDeltaX)
image = dragStartImage
structure = dragStartStructure
```

其中 `stageDeltaX` 是屏幕指针位移除以当前无限画布缩放比例后的舞台坐标位移。

属性栏最小宽度沿用现有 `220px`。本次不设置固定最大宽度；用户可通过无限画布平移、缩放和“适应视图”查看扩大的舞台。

展开态舞台总宽继续由三栏宽度加两条内部分隔线宽度计算。收起态舞台总宽继续由原图、结构恢复条和属性栏宽度计算。由于两个公式都包含属性栏宽度，因此外边缘拖动会自然改变两种状态下的舞台总宽。

## 4. 拖动柄与交互

属性栏右侧增加绝对定位的覆盖式拖动柄：

- 位于属性栏右边缘内侧，不产生新的 Grid 列。
- 视觉边线保持清晰，实际命中区宽于视觉线。
- 悬停和拖动时显示 `col-resize` 光标。
- 使用 `touch-action: none`，避免触摸滚动接管拖动。
- 使用 `role="separator"`、垂直方向语义和明确的辅助名称。
- 展开或收起结构树时始终渲染。

拖动行为：

1. 仅左键启动属性栏调宽。
2. `pointerdown` 捕获指针并记录起始 X、当前三栏宽度和 `property-edge` 边界。
3. `pointermove` 将屏幕位移按当前画布比例换算，再交给纯宽度模型计算。
4. `pointerup`、`pointercancel`、`lostpointercapture`、窗口失焦或组件卸载时清理会话。
5. 所有拖动柄指针事件阻止默认行为和冒泡，不触发画布平移、元素选择或文本选择。
6. 拖动过程中不添加宽度过渡，右边缘即时跟随鼠标。

按用户选择，右边缘不支持双击复位。现有两条内部分隔线的双击复位保持不变。

## 5. 无限画布协作

属性栏右边缘调宽时：

- 当前 `scale`、`x`、`y`保持不变。
- 原图与结构树的舞台坐标和宽度保持不变。
- 舞台右边缘随属性栏宽度向右扩展或向左收缩。
- 不在 `pointermove`或`pointerup`后自动执行“适应视图”。
- ResizeObserver 继续更新舞台测量尺寸。

用户显式点击“适应视图”或双击画布空白区域时，使用调整后的舞台总宽重新计算完整视图。`100%`继续保持当前画布视图中心。

屏幕拖动位移必须除以有效的当前缩放比例；缩放值无效或非正数时安全回退为 `1`。因此在 `20%–400%`范围内，拖动柄都应与屏幕指针同步移动。

## 6. 状态与组件边界

主要改动：

- `apps/region-split-ui/src/panel-layout.ts`
  - 将边界类型扩展为 `property-edge`。
  - 外边缘分支只调整 `property`并应用最小宽度。
  - 内部分隔线的总宽不变语义保持不变。
- `apps/region-split-ui/src/panel-layout.test.ts`
  - 增加外边缘宽度和舞台总宽测试。
- `apps/region-split-ui/src/components/PageOutline.vue`
  - 在属性栏右边缘增加覆盖式拖动柄。
  - 复用现有调宽 pointer 会话和缩放换算。
  - 不为外边缘绑定双击复位。
- `apps/region-split-ui/src/components/PageOutline.test.ts`
  - 增加 DOM、事件隔离、缩放、收起状态和舞台尺寸测试。

属性栏宽度继续只保存在当前页面会话中，不写入后端或本地持久化。

## 7. 异常与边界处理

- 非有限指针位移不改变任何栏宽。
- 属性栏不得缩小到 `220px`以下。
- 无效初始栏宽继续由现有布局模型安全回退。
- 拖动期间结构栏收起、窗口失焦或组件卸载时必须结束会话，不留下调宽光标或 pointer capture。
- 舞台变宽不改变元素百分比坐标、属性 PATCH 数据或图片框位置。
- 属性保存失败不回滚栏宽。
- 右边缘命中区主要位于舞台内部，避免被舞台 `overflow: hidden`裁剪后无法接收指针。

## 8. 测试与验收

### 8.1 纯函数测试

覆盖：

1. 右拖只增加属性栏宽度。
2. 左拖只减少属性栏宽度。
3. 原图和结构树宽度始终不变。
4. 属性栏钳制在 `220px`下限。
5. 非有限位移不改变宽度。
6. 展开态舞台总宽与属性栏宽度同量变化。
7. 收起态舞台总宽与属性栏宽度同量变化。
8. 现有两条内部边界仍保持舞台总宽。

### 8.2 组件测试

覆盖：

1. 属性栏右边缘拖动柄始终存在，包括结构树收起态。
2. 右边缘拖动只改变属性栏和舞台总宽。
3. `220px`最小宽度在组件交互层生效。
4. 非 `100%`缩放时屏幕位移正确换算。
5. 指针捕获和结束、取消、失焦、卸载清理正确。
6. 右边缘事件不触发画布平移和元素选择。
7. 右边缘双击不执行复位。
8. 调宽后“适应视图”和现有两条内部分隔线继续工作。

### 8.3 工程和真实浏览器验收

- UI 全量单元测试通过。
- Vue/TypeScript 类型检查通过。
- 生产构建通过。

  - 展开和收起结构树时均可拖动属性栏右边缘。
  - 右边缘跟随真实鼠标，不出现缩放比例偏差。
  - 左侧两栏位置和宽度不变。
  - 舞台总宽随属性栏宽度变化。
  - 属性栏无法缩小到 `220px`以下。
  - 调宽后滚动、平移、缩放、适应视图和属性编辑正常。
  - 浏览器控制台无错误。

## 9. 明确不做

- 不让右边缘调宽挤压结构树或原图。
- 不增加第三个实际 Grid 分隔列。
- 不为属性栏设置固定最大宽度。
- 不支持右边缘双击复位。
- 不持久化属性栏宽度。
- 不自动执行“适应视图”。
- 不改变后端接口、项目数据或元素坐标模型。
