# UI 效果图区域拆分工具设计

## 1. 背景与目标

UI 效果图直接交给多模态 AI 生成代码，保真度只有约 50%，字体、颜色、间距、组件语义、图标和交互都需要大量人工二次精调。根因是多模态模型擅长语义理解而不擅长像素级测量，且一次性生成没有反馈闭环，所有错误堆到最终代码里才暴露。

改进方向是**两层结构**：外层把页面按模块切分，内层每个模块走自己的微调流程。人负责判断得准的事（结构划分），AI 负责人懒得做的事（命名、生成、诊断）。

本设计只覆盖**外层的第一个核心功能**：上传一张移动端 UI 效果图，AI 把整页拆成 5–10 个粗粒度模块并自动命名，人工可对拆分结果做轻量修正（微调边界、拆分、合并、重命名）。

产物是一份稳定的区域划分 JSON，作为后续所有工作的输入。本设计不涉及代码生成、样式还原和交互推断。

## 2. 核心洞察：粗粒度模块拆分是 Y 轴一维切分问题

移动端页面绝大多数垂直堆叠：模块从上到下依次排列，宽度基本占满屏幕。因此在粗粒度层面，模块边界本质上是**一组水平切分线**，而不是任意矩形。

这带来三个决定性好处：

1. **绕开多模态模型坐标精度不足的问题**。不要求模型输出 `(x, y, w, h)`，只要求它给出"在哪几个 Y 位置切开"。
2. **边界天然首尾相接**，不会重叠、不会有缝隙、不会漏掉页面的任何一块。
3. **工具可以修正模型**。图像水平投影分析能找出真实的分割位置（留白行、分割线、背景色突变行），把模型给出的粗略 Y 值吸附上去，精度从"大概"变成"贴合"。

少数横向并列的元素（底部 tab 的多个图标、并排的两张卡片）在粗粒度下属于同一个模块，不需要横向切分。

**已知限制**：不支持左右分栏式布局的页面。移动端此类布局罕见；若出现，人工可通过拆分/合并近似处理，或降级为单个 `other` 模块留给后续阶段处理。

## 3. 处理流程

```text
上传图片
  → 预处理：读尺寸；抹掉手机系统外壳（状态栏 / Home Indicator），得到同分辨率的干净图；
            过高的长图等比缩放到模型可接受尺寸，记录缩放比
  → 表面分析（工具）：水平投影得候选切分线 + 强度分；面板检测得卡片区间；
                     剔除横穿卡片的候选线
  → 分段（AI）：看干净图 + 候选线 + 卡片区间 → 从上到下的分段，含名称、类型、置信度、滚动标记
  → 融合：AI 的 Y 值吸附到最近候选线；首段顶到 0、末段贴到图底；坐标按缩放比还原
  → 落盘 JSON + 界面可视化
  → 人工修正：微调边界 / 拆分 / 合并 / 重命名（改动实时落盘）
```

### 3.1 预处理：抹掉手机系统外壳

上传的效果图常自带手机状态栏（时间、信号、电量）和底部 Home Indicator，它们不是设计的一部分。预处理在**上传那一刻**执行，不依赖模型——那时还没调模型，而且这样模型根本看不到它们，不会白白占掉一个模块名额。

- **检测**：从上/下边缘向内扫，找**第一段图标簇之后的第一个干净间隙**。不能用"扫描范围内最后一行有图标"——系统外壳和页面内容之间隔着留白，那样会一路吃到导航栏标题上。图标判定阈值不能太低，抗锯齿噪声会把图标簇割开，导致切出过小的假带而漏掉真正的状态栏。
- **重建**：用紧邻的干净行**逐列外推**填充。逐列是关键——状态栏背景常有横向渐变，按行填会丢掉横向变化、出现明显条纹。这是确定性计算，不是生成模型，**不编造内容**。
- **放弃条件**：取样区在垂直方向不平稳（说明相邻的是内容不是背景）时不动任何像素，宁可留着也不硬填。
- **不改分辨率**：只重写像素，绝不缩放裁剪。原图保留在 `image.png` 不动（它是将来像素比对的事实基准），清理结果写 `image.clean.png`；界面、裁剪、分析图都基于清理图。
- 抹掉的带高记入 `image.removedChrome`——**这个高度就是安全区 inset**，下游生成代码时相邻模块的背景要向这个方向铺满。这也是不做物理裁剪的原因：裁掉就把这个信息一起丢了。

### 3.2 归一化与缩放

读取原图尺寸。若图片高度超过模型输入上限（默认 `maxAnalyzedHeight = 2000` 逻辑像素），等比缩小到上限并记录 `analyzedScale = 分析图尺寸 / 原图尺寸`。所有模型返回的 Y 值除以 `analyzedScale` 还原为原图坐标。

界面与存储中的 `bounds` 一律是**原图像素坐标**，不使用分析图坐标。

### 3.3 候选切分线检测

对分析图逐行计算特征，产出候选切分线列表 `{ y, strength }`：

- **留白行**：整行像素方差低于阈值且与页面背景色接近。连续留白行取其中位行作为一条候选。
- **突变行**：本行与上一行的平均色差（Lab ΔE）超过阈值。
- **分割线行**：行内像素高度一致且与上下行都有明显色差、连续高度 ≤3px。

`strength` 由上述证据类型和显著程度归一到 0–1。候选线按 `y` 升序输出。

### 3.4 面板检测与候选线过滤

一维行分析有个绕不过去的盲区：**卡片内部的行间距**和**卡片之间的留白**在像素上完全一样，都是纯色横带。只靠它必然会把卡片从中间切开。

面板检测补上这个二维信息。判据是——一行里有多大比例的像素与**这一行自己的页边距颜色**一致：

- 接近 1 → 整行都是页面底色，这行在卡片之外，可以当模块边界
- 明显小于 1 → 行中间有卡片，横穿它切开是错的

连续的"非敞开行"就是一块面板。落在面板内部的候选线在进入初始划分和模型之前被直接剔除。

两个实现要点：

- **必须逐行取页边距颜色，不能算一个全局底色**。页面顶部常有大面积彩色渐变页头，全局底色会被拽偏，导致哪一行都不匹配、整页被误判成一整块面板。逐行比对天然适应垂直渐变。
- **同色阈值必须小于白卡片与浅灰底的距离**（`rgb(255,255,255)` 到 `rgb(245,245,245)` 只有 17.3）。阈值放宽到 18 就会把卡片当成底色，整个判据失效。

**边缘必须留容差**。候选线取的是留白带的**中位行**，面板边界取的是**颜色变化行**，卡片边缘的抗锯齿让两者天然错开几个像素。用严格的"在区间内"判断会把本就是模块边界的候选线误删——实测商品区面板是 `[1937, 2283]`，而它与底部导航之间的真边界候选线在 `y=2279`，只差 4 像素就被剔除，导致整页底部 20% 一条候选线都不剩，底部导航栏无法单独成块。

正确做法是：**贴近面板边缘的候选线先吸附到边缘再判断**，只剔除真正深入内部的。吸附本身总是安全的——面板边缘按定义就是合法切分位置，几条近边线吸附后会合并成一条。

面板区间同时写入文档并送给模型，提示词要求切分位置不得落在面板内部。

### 3.5 AI 分段

单次模型调用，输入清理后的分析图 + 候选线 Y 值 + 卡片区间，要求输出从上到下、连续无缝的分段：

```json
{
  "regions": [
    { "displayName": "状态栏", "id": "status-bar", "type": "status-bar",
      "yStart": 0, "yEnd": 44, "confidence": 0.96 }
  ]
}
```

提示词约束：分段数量控制在 5–10 个；必须从 0 开始、到图底结束；`yEnd` 等于下一段的 `yStart`；`id` 为 kebab-case 英文标识；`displayName` 为简短中文名；**切分位置不得落在任何卡片内部**。

模型输出经 Schema 校验；失败时重试一次，再失败则报错并保留原图供人工从零手动拆分。

单次模型请求默认 120 秒超时（配置文件可用 `timeoutMs` 覆盖）。这个值不是用来约束响应速度的，只是兜住"连得上但永远不回包"的挂起——实测整页分段要十几到几十秒，设得太紧会时好时坏地误杀正常请求。

### 3.6 滚动属性推断

每个模块附带 `scrollX` / `scrollY`，直接对应 CSS 的 `overflow-x` / `overflow-y`，下游生成代码时是机械映射。两者的可推断性差别很大，提示词里分开约束：

- **`scrollX` 可以从单张截图取证**：最右侧卡片只露出一半、一行等宽卡片明显放不下、带分页圆点的轮播。没有这类证据就是 `false`。
- **`scrollY` 几乎无法取证，且有个陷阱**：移动端页面整体都能上下滚，模型很容易把每个模块都标成 `true`。提示词明确写死"页面自身的滚动不是模块属性"，只有模块是固定高度的内嵌滚动面板（有独立滚动条、内容在模块下边缘被裁断）才为 `true`，拿不准填 `false`。

模型未给这两个字段时按 `false` 处理，旧文档同样可读。拆分/合并产生的新块把它们重置为 `false`（与 `displayName`/`type` 一致），交给随后的自动 AI 重命名重新判断。

### 3.7 融合与修正

按顺序执行，保证输出必定合法：

1. 按 `yStart` 升序排序。
2. 每条边界（相邻两段的交界）吸附到最近候选线——距离在 `snapThreshold`（默认 12px）内才吸附，且优先吸附 `strength` 高的候选线。
3. 消除重叠与缝隙：相邻段以吸附后的边界为准，前段 `yEnd` 与后段 `yStart` 强制相等。
4. 首段 `yStart` 置 0，末段 `yEnd` 置图高。
5. 丢弃高度小于 `minRegionHeight`（8px）的段，将其并入上一段。
6. `id` 去重：重复时追加 `-2`、`-3` 后缀。
7. Y 值按 `analyzedScale` 还原为原图坐标。

## 4. 数据结构

```ts
interface Rect { x: number; y: number; w: number; h: number }

type RegionType =
  | "status-bar" | "nav-bar" | "banner" | "card" | "grid"
  | "list" | "form" | "tabs" | "text-block" | "action-bar" | "tab-bar" | "other";

interface Region {
  id: string;           // 稳定机器标识，kebab-case，如 "member-info-card"
  displayName: string;  // 可重命名的中文名，如 "会员信息卡"
  type: RegionType;     // 模块类型，决定后续阶段的内部工作流
  bounds: Rect;         // 原图像素；x 恒为 0，w 恒为图宽
  confidence: number;   // 0–1
  scrollX: boolean;     // 区域整体可横向滑动，对应 overflow-x
  scrollY: boolean;     // 区域整体可纵向滑动，对应 overflow-y
}

interface RegionSplitDoc {
  schemaVersion: string;
  image: {
    fileName: string;
    width: number;          // 原图像素
    height: number;
    analyzedScale: number;  // 分析图 / 原图
    // 预处理抹掉的系统外壳横带；高度即安全区 inset
    removedChrome: { edge: "top" | "bottom"; height: number }[];
  };
  regions: Region[];        // 按 y 升序，首尾相接覆盖全图
  candidateLines: CandidateLine[];  // 原图坐标，供拆分模式吸附
  panels: Panel[];          // 检测到的卡片区间，模块边界不得横穿
  updatedAt: string;
}

interface CandidateLine { y: number; strength: number }  // y 为原图坐标
interface Panel { top: number; bottom: number }         // 原图坐标，闭开区间

interface ModelConfig {
  baseUrl: string;    // OpenAI 兼容端点，如 http://127.0.0.1:11434/v1
  apiKey: string;     // 本地模型可留空
  model: string;      // 模型名
  timeoutMs?: number; // 单次模型请求超时，缺省 120000
}
```

不设 `reason` 字段：人直接看图上的分段判断对错，比读模型的解释更快，且人已具备直接修正的能力。

### 4.1 不变量

以下条件在任何操作后都必须成立，由服务端在每次写入前校验：

- `regions` 按 `bounds.y` 升序，且相邻区域 `前.y + 前.h === 后.y`
- 首区域 `y === 0`，末区域 `y + h === image.height`
- 所有区域 `h >= 8`
- 所有区域 `x === 0`，`w === image.width`
- `id` 全局唯一

违反不变量的写入一律拒绝并返回错误，不做静默修正。

## 5. 界面与交互

### 5.1 布局

```text
┌──────────────────────────────────────────────────────────┐
│ [选择图片] [重新分析]      qwen2.5vl:7b   [撤销] [重做]    │ 全局工具栏
├──────────────────────────────────────────────────────────┤
│ 已选：会员信息卡   [▲][▼] 微调下边界  [拆分] [重命名] [AI 重命名] │ 上下文操作条
├───────────────────────────────┬──────────────────────────┤
│                               │  1  状态栏         0.96   │
│    原图 + 分段色块叠加          │  2  顶部导航       0.94   │
│    选中：蓝色高亮               │  3  会员信息卡 ←   0.88   │
│    下边界：粗蓝线               │  4  权益对比表     0.82   │
│                               │  5  套餐选择       0.85   │
├───────────────────────────────┴──────────────────────────┤
│ y 220 → 386   h 166        ↑↓ 微调下边界 · Ctrl+Z 撤销      │ 状态条
└──────────────────────────────────────────────────────────┘
```

分段色块使用交替的低饱和色，左上角标签显示序号和 `displayName`。图片按容器宽度等比缩放显示，所有交互坐标经视图缩放比换算回原图坐标。

右侧列表项与图上色块双向联动：hover 互相高亮，点击互相选中，选中项滚动进视野。

### 5.2 上下文操作条

操作条内容随选中状态变化，这是交互的主干：

| 选中状态 | 操作条显示 |
|---------|-----------|
| 未选中 | 空 |
| 单个区域 | `[▲][▼] 微调下边界` `[拆分]` `[重命名]` `[AI 重命名]` |
| 多个相邻区域 | `[合并]` |
| 多个不相邻区域 | `[合并]` 禁用，提示"只能合并相邻区域" |
| 拆分模式中 | `拆分「会员信息卡」— 移动鼠标选择位置，点击确认` `[取消]` |

末区域选中时 `[▲][▼]` 禁用（其下边界固定为图底）。

### 5.3 选中

- 点击图上色块或右侧列表项：选中单个。
- `Ctrl + 点击` 或 `Shift + 点击`：加选/取消加选。
- 点击图片空白处或按 `Esc`：清空选中。

### 5.4 编辑操作

**微调边界**：选中单个区域后，`[▲]` / `[▼]` 按钮各点击一次调整该区域下边界 1px，长按连续触发（首次延迟 400ms，之后每 60ms 一次）。上下方向键做同样的事。本区域高度变化，下方相邻区域反向变化，总高恒定。调整受 `minRegionHeight` 约束，到极限即停止响应。

**拆分**：点 `[拆分]` 进入拆分模式。该区域内出现一条跟随鼠标的水平线，线旁实时显示 Y 值与上下两段高度。行为：

- 鼠标位置距离某条候选切分线在 `snapThreshold` 内时自动吸附，并将线加粗提示吸附生效。
- 鼠标进入区域顶部或底部 8px 内时线变红，点击无效。
- 点击有效位置完成拆分；`[取消]` 或 `Esc` 退出拆分模式。

**合并**：选中多个相邻区域后点 `[合并]`，立即合并为一个区域，`bounds` 取并集。

**拆分/合并后自动重新命名**：结构变化后原名称不再准确，系统自动将新区域的裁图发给模型，重新获取 `displayName`、`id`、`type` 和滚动标记。请求期间新区域显示"命名中…"占位；模型未配置时直接跳过（新块保持占位名，不发请求也不报错）；失败或超时则静默保留占位名 `未命名区域`、`type` 为 `other`，人工可点 `[AI 重命名]` 重试——这是自动的锦上添花，不该弹错误打断用户。

**重命名**：点 `[重命名]` 或双击列表项名称，就地变为输入框；`Enter` 或失焦提交，`Esc` 取消。仅修改 `displayName`，`id` 保持不变。

**AI 重命名**：点 `[AI 重命名]` 对当前选中的单个区域重新获取名称、`id` 和 `type`。

**重新分析**：丢弃全部现有区域并重跑完整流程。因会覆盖人工修改，需二次确认。模型未配置时按钮禁用，提示"请先配置模型"。

### 5.5 模型配置

模型配置**只在项目配置文件里维护，界面上没有配置入口**：

```text
ui/region-split.config.json     含 API Key，不入版本库
ui/region-split.config.example.json   提交进版本库的模板
```

```json
{ "baseUrl": "http://127.0.0.1:11434/v1", "model": "qwen2.5vl:7b", "apiKey": "" }
```

界面对配置**只读不写**：

- 已配置时，工具栏右侧显示当前模型名。
- 未配置时显示提示徽标"未配置模型：请编辑 region-split.config.json"，`title` 里给出完整路径（路径由服务端提供，因为只有它知道自己在读哪个文件）；`[重新分析]` 与 `[AI 重命名]` 同时禁用。

这样做的取舍：少了界面上的即时反馈，换来 API Key 完全不经过浏览器、也不存在"能通过 HTTP 改写服务端配置"的入口。连通性自检改由服务端提供（`POST /api/model-config/check`），它只用自己配置文件里的配置，不接受请求体。

配置每次请求都重读，改完文件即时生效，不必重启服务。

### 5.6 进行中状态

上传、载入、AI 分析期间，内容区盖一层遮罩，标明当前在做什么（"AI 分析中…"），并说明"分析期间无法编辑，完成后自动解锁"。

遮罩只盖内容区不盖工具栏——工具栏的按钮已按状态逐个禁用，盖住反而看不到进度。

**遮罩只是视觉拦截，不是唯一防线**。所有会改动区域的动作（微调、拆分、合并、重命名、AI 重命名、再次分析）在 store 里都有独立守卫，进行中一律直接返回。键盘和程序化调用绕得过遮罩，绕不过守卫。真实模型分析要十几到几十秒，没有这两层的话用户会在等待期间继续编辑，而结果返回后 `setDoc` 会把这些编辑全部覆盖掉——改了半天白改，且没有任何提示。

### 5.7 撤销与重做

`[撤销]` / `[重做]` 按钮，同时支持 `Ctrl+Z` / `Ctrl+Shift+Z`。

实现为 `regions` 数组的快照栈（数据量小，直接深拷贝）。快照时机：

- 拆分、合并、重命名、AI 重命名、重新分析：操作前压栈。
- 边界微调：连续调整合并为一次快照——首次调整时压栈，之后 500ms 内的连续调整不再压栈，超过 500ms 无操作则下一次调整重新压栈。

栈深上限 50。执行新操作时清空重做栈。

## 6. 服务端接口

```text
POST /api/projects                           上传图片（multipart），创建项目，返回 { projectId, image }
POST /api/projects/:projectId/analyze        跑完整拆分流程，返回 RegionSplitDoc
GET  /api/projects/:projectId                读取 RegionSplitDoc
PUT  /api/projects/:projectId/regions        整体写入 regions（校验不变量后落盘）
POST /api/projects/:projectId/regions/:id/rename-ai   对单个区域调用模型重新命名
GET  /api/projects/:projectId/image?rect=x,y,w,h      取原图或其裁剪
```

模型配置接口（**只读**，没有写入接口）：

```text
GET  /api/model-config          返回 { baseUrl, model, hasApiKey, configPath }，不含明文 key
POST /api/model-config/check    用服务端自己的配置发一个最小请求做连通性自检，返回 { ok, error? }
                                不接受请求体，因此不存在把已存 Key 引向任意地址的路径
```

`projectId` 由服务端在上传时生成（时间戳 + 短随机串，如 `20260811-a3f9`），前端拿到后写入 URL hash，刷新页面可恢复现场。界面初次打开无 `projectId` 时只显示"选择图片"。

未配置模型时，`analyze` 与 `rename-ai` 返回 400 `{ error: "model not configured" }`，前端在工具栏提示该去编辑哪个配置文件。

`PUT regions` 采用整体替换而非增量补丁：`regions` 数组小，前端持有完整状态，整体写入实现简单且不变量校验直接。撤销/重做在前端完成，每次状态变化后调用一次 `PUT`。

### 6.1 存储

```text
ui/
  region-split.config.json         模型配置（含 API Key，不入版本库）
  region-split.config.example.json 模板（入版本库）
  data/
    projects/<projectId>/
      image.png                    上传的原图
      image.analyzed.png           缩放后的分析图（用于模型调用与候选线检测）
      regions.json                 RegionSplitDoc
```

模型配置的读取优先级：配置文件存在则用文件；否则回落到环境变量 `UIR_MODEL_BASE_URL` / `UIR_MODEL_API_KEY` / `UIR_MODEL_NAME`（便于 CI 或容器部署）。配置文件路径由服务端从模块自身位置推导，不依赖 cwd，可用 `UIR_CONFIG_FILE` 覆盖。`data/` 与 `region-split.config.json` 都进 `.gitignore`。

## 7. 技术选型

| 项 | 选择 | 理由 |
|----|------|------|
| 语言/运行时 | TypeScript，Node ≥22 | 与既有仓库一致 |
| 图像处理 | sharp | 尺寸读取、缩放、裁剪、raw 像素读取 |
| 候选线检测 | 自实现水平投影分析 | 逻辑简单（百行内），纯函数易测 |
| 模型接入 | OpenAI 兼容 Chat Completions | 不绑厂商，本地模型或中转站均可；配置来自项目文件 `region-split.config.json`，环境变量兜底。模型客户端**按请求构造**，改配置文件即时生效、不必重启 |
| 输出校验 | zod | 与既有 `packages/contracts` 一致 |
| 服务端 | Fastify | 轻量、TS 友好 |
| 前端 | Vue 3 + TypeScript + Vite | 与既有仓库一致 |
| 测试 | Vitest；模型调用一律注入 fake | 不打真实网络 |

## 8. 实施顺序

分两步，每步都能看到实际效果：

1. **纯模型分段跑通闭环**：上传 → 模型直接分段 → 融合（不含吸附）→ 界面可视化 + 全部人工编辑功能。此时已是可用工具。
2. **加候选线检测与吸附**：接入 `candidate-lines`，在融合中启用吸附，并在拆分模式中启用吸附提示。对同一批图片对比第 1 步的结果，量化吸附带来的边界精度提升。

## 9. 验收标准

以 3 张真实移动端 UI 效果图（含一张长图）验收：

1. 上传后自动完成拆分，模块数在 5–10 之间，无重叠、无缝隙、覆盖全图。
2. 人工修正达到满意划分的操作次数 ≤ 10 次（微调、拆分、合并、重命名合计）。
3. 拆分模式下候选线吸附命中真实分割位置，人工无需再逐像素微调。
4. 拆分/合并后自动命名在 15s 内返回且名称语义正确。
5. 撤销可连续回退 10 步以上，状态无错乱；刷新页面后结果与落盘 JSON 一致。
6. 不变量在任何操作序列后都成立。
7. 在 `region-split.config.json` 里配置一个本地模型端点，`POST /api/model-config/check` 返回 `ok`，随后分析可用；改成错误端点后自检给出明确失败原因；`GET /api/model-config` 的响应不含明文 API Key。
