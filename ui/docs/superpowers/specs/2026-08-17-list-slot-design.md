# 列表与槽位设计

2026-08-17

同一个父级下的一组平级元素,在页面上应当保持统一的宽高与间距——对应 HTML 里的 `ul > li`。
本文把这个概念在数据、检测、界面、生成器四处补完整。

---

## 1. 这个概念已经在了,叫 `grid`

不需要发明新东西。`element-detect.ts:178-183`:

```ts
const repeat = detectRepeat(boxes, direction);
if (repeat && template) {
  parent.kind = "grid";                                       // ← 同一个条件
  parent.repeat = { count, templateId, pitch };
}
```

**`kind === "grid"` 与 `repeat !== undefined` 是同一个判断的两个出口。** "网格"这个类型本身就是
"这一层是等距重复"的标签,不是另一个独立判断。

### 实测:判得很准

跑遍现有全部项目的元素树,统计所有有 ≥2 个流内子元素的容器:

```
repeat=是   6 组   全部是 grid，子元素 3–5 个
repeat=否  30 组   全部是 component，子元素恰好 2 个
```

6 组正例:

```
登录/注册      ×3  pitch 117.0   子高 338/338/338
登录/注册      ×3  pitch 120.0   子宽 56/52/54   子高 56/52/58
功能入口栏      ×5  pitch 219.8   子高 87/87/87/87/87
卡券与钱包入口列表  ×5  pitch 219.8
优惠资产信息     ×5  pitch 219.8
快捷功能菜单     ×5  pitch 219.3   子高 132/134/172/129/134
```

30 组反例**全是恰好两个子元素的异构组合**,不是列表:

```
扫一扫   64×58 + 91×28      品类码   70×56 + 91×34
联系客服  76×63 + 130×28     收货地址  62×68 + 129×28
```

**零误报,零漏报。** 判据本身不需要改。

### 因此:不要把 `detectRepeat` 的"至少 3 个"门槛放宽到 2

上面 30 组反例全是双子元素。放宽到 2 会把「图标 + 文字」这种最常见的真实结构
整批误判成列表。真遇到两项的列表,由人工标记(见第 3 节)。

---

## 2. 缺陷一:两个字段会脱节

一起赋值只发生在**检测**那一次。之后人工一动就分家,两条路都已验证:

| 路径 | 现状 | 结果 |
|---|---|---|
| `element-state.ts` 的 `setKind` | 清 `borderRadius`、清 `textBox`,**不碰 `repeat`** | 把 grid 改成 component,身上还挂着 `repeat: {count:5, pitch:219.8}` 的孤儿数据 |
| `element-layout.ts` 的 `recomputeLayout` | 等距不成立时 `delete next.repeat`,**从不改 `kind`** | 留下一个叫"网格"、却没有重复信息的容器 |

### 决策:两处同步(而不是合并字段)

考虑过三种做法:

- **A. 让 `grid` 变成派生值**(不存 kind,看 `repeat` 有没有):最干净,但 `kind` 是人工可编辑的
  下拉项,取消掉会少一种人工表达方式。
- **B. 两处同步**:补两个已有函数的收尾动作。
- **C. 合并成一个字段**(去掉 `kind: "grid"`):要动 schema 和界面。

**取 B。** A 和 C 都要动 schema 与界面,而 B 只是补收尾;更重要的是 B 保留了"人工把某个容器
标成网格"这个能力——第 1 节的门槛决定了**两项的列表只能靠人工标**,这个能力不能去掉。

具体规则:

1. `setKind` 改离 `grid` 时,一并删掉 `repeat`。
2. `recomputeLayout` 删掉 `repeat` 时,把 `kind` 降回 `component`——**除非该节点
   `classification === "human"`**。人工定的类型不许被几何推翻,这与项目里
   `scrollOverrides` 保留人工滚动值是同一条原则。

---

## 3. 缺陷二:只记了间距,没记槽位

```ts
repeat?: { count: number; templateId: string; pitch: number }
```

`pitch` 是项与项的间距,而"每项统一多大"没有地方放。补上:

```ts
repeat?: {
  count: number;
  templateId: string;
  /** 主轴上相邻项的中心距 */
  pitch: number;
  /** 槽位尺寸。子元素的墨迹居中放进去，不拉伸。 */
  slot: { w: number; h: number };
  /** 槽位是谁定的。human 的不被几何重算冲掉。 */
  slotBy: "tool" | "human";
}
```

### 核心:槽位与墨迹框是两个东西,不能合并

- **槽位**属于容器,统一,决定布局 —— 就是 `li` 的盒子
- **墨迹框**属于每个子元素,各不相同,是测量结果 —— 就是 `li` 里面画的东西

实测那三个图标 `56/52/54 × 56/52/58`:**这不是测量误差**。气泡、二维码、齿轮三个图标
本身画得就不一样大,设计稿里它们共用一个槽位,但各自的笔画外延不同。

**强行把三个墨迹框拉成一样大,等于把槽位和墨迹混为一谈,图标会被拉变形。**

这与项目里已有的两条结论同源:

- 文字:**墨迹框 ≠ 行盒**(见 `2026-08-17-codegen-and-fidelity-design.md` 第 3.3 节)
- 图标:**墨迹框 ≠ 图标画布**(本节)

处理方式也相同:**盒子按槽位画,墨迹居中放进去。**

### 槽位取中位数,不取最大值

「快捷功能菜单」×5 的子高是 `132/134/172/129/134`。取最大值会被那个 172 把整行撑高。

取中位数,**并把偏离超过阈值的子项标出来**——这与字号量化里"簇内离散度当质量指标"
是同一个用法:**不一致本身就是"这一项检测错了"的信号**。172 那个多半是框切错了,
不是设计如此。

> 偏离阈值待实测标定。现有样本里,正常项与中位数的差是 0–3(如 132/134 对中位 134),
> 离群项是 38(172 对 134)。缺口很大,但只有一个离群样本,不足以定阈值。

### 槽位的重算与人工覆盖

`slot` 与 `layout` 一样,是**纯几何**,由 `recomputeLayout` 按子块矩形重算。
人工改过的槽位记 `slotBy: "human"`,重算时保留——与 `scrollOverrides` 保留人工滚动值一致。

**人工改槽位不改动任何子元素的 `box`。** 槽位只影响生成时的布局,墨迹框始终是测量结果。

## 4. 生成代码:概念在这里兑现成 `ul > li`

```css
.e-g { display: flex; flex-direction: row; }
.e-g > * {                 /* 5 个子元素只出这一条规则 */
  width: 18.7821vw;        /* pitch */
  height: 11.4530vw;       /* slot.h */
  display: flex;
  justify-content: center;
  align-items: center;
  flex: 0 0 auto;
}
```

**5 条几乎相同的规则塌成 1 条**——CSS 不再自我重复,这正是 `ul > li` 在样式表里的样子。
转小程序时这一条直接对应 `wx:for` 的 item 样式。

主轴尺寸用 `pitch` 而不是 `slot.w`:`pitch` 是中心距,它才是让项等距排开的那个量。
`slot.w` 用于交叉轴是列的场景(`flex-direction: column` 时用 `slot.w` 定宽、`pitch` 定高)。

这条规则已经写在 `2026-08-17-codegen-and-fidelity-design.md` 第 2 节
(重复组按 `pitch` 出等宽格子),本文把它的另一半——槽位的**交叉轴尺寸**——补齐。

---

## 5. 界面呈现

- **结构树**:`grid` 节点显示 `列表 ×5`,而不是现在的类型角标 + 数量分开显示。
- **属性面板**:容器多一组 **槽位 W / H + 间距**,可编辑。改槽位所有项跟着变——
  这就是"保持同等值"的落点。
- **子项**:标出**偏离槽位多少**。偏得多的就是该回去看框的那一项。

---

## 6. 明确不做

- 不放宽 `detectRepeat` 的 ≥3 门槛(第 1 节有数据)。
- 不自动统一子元素的 `box`(第 3 节:那会把图标拉变形)。
- 不把 `kind: "grid"` 从 schema 里去掉(第 2 节:保留人工标记两项列表的能力)。

---

## 7. 遗留未定项

- 第 3 节槽位偏离的告警阈值需在更多数据上标定,现有样本只有一个离群点。
- 交叉轴为列时 `slot.w` 与 `pitch` 的分工需要一个真实的竖向列表样本验证,
  现有 6 组正例全是横排。
- 人工标记两项列表的入口(改 `kind` 为 grid 之后,`repeat` 从哪来)尚未设计——
  几何算不出 `count`/`pitch` 时,是让人填还是从两个子块直接推,待定。
