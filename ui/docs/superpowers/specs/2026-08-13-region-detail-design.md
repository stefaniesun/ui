# 区域详情面板设计

## 背景

区域拆分工作台已经能把整页切成 5–10 个模块。下一步是进入单个模块，把它内部的元素和层级解析出来——这是把模块还原成 HTML 的前提：`display:flex` 还是 `grid`、间距是 `gap` 还是 `margin`、圆角背景属于哪一层，全部来自层级。

本设计定义**区域详情面板**：选中单个区域后，在画布上出现的第二个节点，用来查看和人工修正该区域的元素解析结果。

## 分阶段

一次做完整套解析会让改动面过大、界面风险堆在最后。按**能独立跑通并验收**的切片推进：

| 阶段 | 交付 | 验收方式 |
|---|---|---|
| **一** | 面板本体 + 顶层容器识别 + 人工编辑 | 界面上看得见、改得动、存得住 |
| 二 | 容器内递归切分、布局量（方向/gap/padding）、网格与滚动 | 真实截图回归断言 |
| 三 | 模型判定叶子是文字还是图标，并命名 | 假模型单测 + 真实调用 |

**本设计覆盖全部三个阶段的目标形态，但阶段一必须先独立跑通、经人工确认界面无误之后，才开始阶段二。** 阶段二、三的实施计划在阶段一验收后另写。

## 界面结构

### 位置

画布上新增第二个节点 `detail`，位于现有 `workspace` 节点右侧。

- 未选中区域：显示「选择一个区域查看详情」。
- 选中恰好一个区域：显示该区域详情。
- 多选：显示「请选择单个区域」。
- 区域处于拆分模式：整体禁用。

### 上下布局

节点内是**上下两段**，不是左右分栏：

```
┌─────────────────────────────────┐
│ 操作条（解析 / 状态）            │  42px
├─────────────────────────────────┤
│                                 │
│        区域原图 + 元素标注       │  宽度占满，高度由宽高比决定
│                                 │
├──────────────────┬──────────────┤
│                  │              │
│    结构树        │   元素属性    │  320px
│                  │              │
└──────────────────┴──────────────┘
```

节点宽 `760px`。下段用 `grid-template-columns: minmax(0, 1fr) 300px`，与现有 `.comparison-workspace` 的 `minmax(0, 1fr) 245px` 是同一套写法。

选上下而不是左右的原因：区域裁图的宽高比跨度极大（分类胶囊行 `1170×85`，商品推荐区 `1170×595`）。左右分栏会把图挤成窄条，上下则让图始终占满节点宽度，宽高比再极端也只影响自身高度。

### 图区不做高度上限

上段的图**始终等于节点宽度**，高度由 `aspect-ratio: 区域宽 / 区域高` 决定，不设 `max-height`。

这样元素标注框可以**全部用百分比定位**，不需要任何 `ResizeObserver` 测量：

```
left  = (box.x - region.x) / region.w × 100%
top   = (box.y - region.y) / region.h × 100%
width =  box.w / region.w × 100%
height=  box.h / region.h × 100%
```

一旦给图加高度上限并配 `object-fit: contain`，图的实际渲染矩形就不再等于容器矩形，标注必须改回测量式定位——那是上一版界面出问题的根源之一。高区域会让节点变高，但画布本来就能缩放和拖动，这个代价可以接受。

### 结构树

缩进列表，行样式沿用 `RegionList.vue`：类型徽标 + 名称 + 简要信息。

- 单击选中，与图上的标注框双向联动（沿用现有 `hoveredId` 的做法）。
- 双击名称就地重命名。
- 选中行显示删除按钮。

### 元素属性

右下角的属性面板，显示当前选中节点的信息，并提供可编辑项：

| 属性 | 阶段 | 可编辑 |
|---|---|---|
| 名称 | 一 | 是 |
| 类型 | 一 | 是（下拉） |
| 位置尺寸 `x / y / w / h` | 一 | 否（测量结果） |
| 背景色 | 一 | 否 |
| 内部主色占比 | 一 | 否（诊断用） |
| 布局方向 / gap / padding | 二 | 否 |
| scrollX / scrollY | 二 | 是（覆盖几何判定） |
| 重复次数 | 二 | 否 |

未选中节点时显示「选择一个元素查看属性」。

## 元素分类

分两层，不是并列的几类。这个二分决定了每个节点能做什么操作。

**容器类（有子节点，对应 `<div>`）**

- `component` — 组件。
- `grid` — 子节点等距同构的组件（阶段二产出）。

**叶子类（无子节点）**

- `text` — 文字，对应 `<span>`。
- `icon` — 可矢量化图形，对应 `<svg>`。
- `image` — 必须切位图，对应 `<img>`。
- `decoration` — 纯装饰。

`icon` 与 `image` 的界线按**还原方式**定义，不按外观或尺寸。

阶段一只产出 `component` 和 `image` 两种——前者由内部主色占比高判定，后者由占比低判定。其余类型此阶段只能由人工在属性面板里指定。

## 数据模型

元素树存独立文件 `elements.json`，**不进 `regions.json`**。

这样 `regionSplitDocSchema` 与 `checkInvariants` 一行都不用改，区域撤销栈仍然只承载 `Region[]`，两种编辑互不污染。

```
{
  "schemaVersion": "1",
  "trees": [{
    "regionKey": "396-618",
    "detectedAt": "2026-08-13T…",
    "nodes": [{
      "id": "n1",
      "parentId": null,
      "box": { "x": 36, "y": 396, "w": 1098, "h": 222 },
      "kind": "component",
      "displayName": "节点 1",
      "style": { "background": "#ffffff" },
      "uniformity": 0.93,
      "source": "auto",
      "classification": "tool"
    }]
  }]
}
```

- `box` 一律**原图坐标**，与 `regions`、`candidateLines`、`panels` 同一坐标系。
- `source` 取 `auto` / `manual`；`classification` 取 `tool` / `model` / `human` / `uncertain`。
- 阶段二追加 `layout`、`scrollX`、`scrollY`、`repeat`；阶段三写入 `namedAt`。字段一次性定义在 schema 里，阶段一不产出的留空即可，避免后面改 schema。

### 用 `regionKey` 而非 `regionId`

树按**区域的几何边界**索引，键为 `"{bounds.y}-{bounds.y + bounds.h}"`。

区域 id 会在 AI 重命名、拆分、合并后变化，用它索引会让已经人工确认过的树凭空孤立。边界是稳定的：只要那条线没被移动，树就仍对应同一块像素。边界确实变了，旧树按新键取不到，界面回到「未解析」——区域范围变了，树本来就该重算。

### 不变量

写盘前校验，违反返回 `422`：

- 子节点的 `box` 完整落在父节点 `box` 内，根节点落在区域矩形内。
- `parentId` 指向树内已存在的节点，且不成环。
- `id` 树内唯一。
- 兄弟节点之间不重叠。
- 叶子类型的节点没有子节点。

## 检测（阶段一）

只做顶层容器，全部确定性计算，**不调用模型**。在清理图 `image.clean.png` 上进行。

1. 取区域左右各 `6px` 边距像素的中位色作为区域底色。
2. 与底色最大通道差 `> 8` 的像素构成内容掩膜。
3. 求四连通块，丢弃宽 `< 80` 或高 `< 24` 的块，其外接矩形即候选容器。
4. 每块计算内缩 `4px` 后的内部主色与占比。
5. 占比 `<= 0.1` 判为 `image`；否则判为 `component`，并记下 `style.background`。

### 实测依据

以下数值来自 `test-fixtures/maicai.png`（1170×2532 移动端首页），不是估计值：

- 页面底色 `rgb(245,245,245)`。
- 内部主色占比：白卡片 `0.83`–`0.96`，采购横幅 `0.02`，混合内容约 `0.64`。一个数就把 `<div>` 和 `<img>` 分开。
- 顶层容器实测能干净框出：卡券资产 `(36,396,1098,222)`、订单状态 `(36,645,1098,249)`、三张优惠券卡、常用服务 `(36,1131,1098,255)`、采购横幅 `(36,1413,1098,216)`、五个分类胶囊、头像圆形。

### 已知失败面

**白底连着白底会并块。** 实测底部商品网格与 tab 栏被并成一个 `1170×595` 的块。这是连通域方法的固有局限，解法是阶段二进入该块后继续递归，**不是**把第一刀的阈值调准。阶段一必须如实呈现这个合并结果，界面上人工可以手动补框拆开它。

## 人工编辑（阶段一）

- **重命名** — 树上双击或属性面板里改。
- **改类型** — 属性面板下拉，`classification` 随之变为 `human`。
- **删除节点** — 子节点上提到父节点，**不级联删除**。这是「拍平多余的一层」，最常见的修正动作。
- **框选新增容器** — 在图上拖一个矩形；父节点取包含该矩形的最深节点，被该矩形完整包含的现有兄弟自动成为它的子节点。这正是补一层不可见容器——不可见容器在图上不留任何痕迹，原理上无法检测，只能人工加。
- **重新解析** — 丢弃当前树重跑，`source` 为 `manual` 的节点不保留，需二次确认。

### 不提供撤销栈

元素编辑的每个动作都可直接反向操作（删除后重新框选，新增后删除）。`Ctrl+Z` 仍然只作用于区域编辑，不接管元素编辑——把两种状态混进同一个 `Region[]` 栈只会互相污染。

树行获得焦点时 `Delete` 删除该节点。

## 非目标

- 不识别文字内容，不做 OCR，不测字号与颜色。
- 不推断不可见容器（没有背景色、边框、阴影的 `<div>` 在图上不留痕迹）。
- 不生成 HTML/CSS。
- 不让模型给出任何坐标或尺寸。位置一律来自测量。
- 不改变区域拆分的任何行为、数据或不变量。
- 不修改 `apps/region-split-ui/src/state.ts` 的任何既有导出成员。
- 不提供拖拽改父子关系。删除加新增已能表达同样结果，拖拽重连的交互与校验成本高得多。

## 画布改动

保持最小，不做通用化改造：

- `canvas-state.ts` 的 `NodeId` 扩为 `"workspace" | "detail"`，`DEFAULT_NODE_POSITIONS` 增加 `detail`。
- `NODE_POSITIONS_STORAGE_KEY` **保持 `:v2` 不变**——`loadNodePositions` 按 `fallback` 的键遍历，旧存档缺 `detail` 会自动回落到缺省值；升版本号只会白白丢掉用户摆好的 workspace 位置。
- `PipelineCanvas.vue` 的 `onNodeDragStart` 目前硬编码 `positions.workspace`，改为按传入的 `nodeId` 写。`PipelineNode` 已经通过 `dragStart` 事件透传了 `nodeId`。
- `contentBounds()` / `fitAll()` 覆盖两个节点的并集包围盒。
- 节点根元素加 `@pointerdown.stop`，与 `RegionsNode.vue` 一致，否则图上的框选拖拽会被画布平移吞掉。

**本阶段不画连线、不启用端口。** 端口样式已在 `PipelineNode.vue` 里实现但被 `:input="false" :output="false"` 关闭，保持关闭；连线是视觉锦上添花，与功能无关，留到界面稳定之后再说。

## 验收标准（阶段一）

1. 选中单个区域后，画布右侧出现「区域详情」节点；未选中或多选时显示对应提示。
2. 节点内为上下结构：上为区域裁图，下为结构树与元素属性。
3. 图始终占满节点宽度，宽高比与区域一致；换选不同高矮的区域都不变形。
4. 点「解析元素」后，图上出现容器标注框，树与之对应。
5. 常用服务、卡券资产、采购横幅三张卡片都能被框出；横幅判为 `image`，另两张判为 `component`。
6. 底部商品区与 tab 栏被并成一块——这是已知失败面，界面如实呈现，人工可框选拆开。
7. 点击树行或图上的框，两侧同步高亮，属性面板显示该节点的名称、类型、坐标尺寸、背景色与主色占比。
8. 人工可重命名、改类型、删除节点（子节点上提）、框选新增容器；结果落盘，刷新后仍在。
9. 元素编辑不影响区域数据，`Ctrl+Z` 仍只撤销区域编辑。
10. 区域边界改变后，该区域显示为未解析。
11. 拖动「区域详情」节点只有它移动；「适应窗口」能同时容纳两个节点。
12. 区域拆分工作台的全部既有功能与测试保持通过。
