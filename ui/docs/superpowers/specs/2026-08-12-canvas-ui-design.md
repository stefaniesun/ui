# 区域拆分工具 · 画布式深色界面改造设计

面向实现者的开发文档。**只改界面，不改任何功能。**

现有功能设计见 [2026-08-11-region-split-design.md](2026-08-11-region-split-design.md)，本文不重复其中的算法与数据结构。

---

## 1. 目标

把现在这套朴素的"工具栏 + 图 + 列表"三栏界面，换成 ComfyUI 那种**深色无限画布 + 节点 + 连线**的形态。

打开网页即是一张可平移缩放的无限画布，流水线的每一步是画布上的一个节点，节点之间用连线表示数据流向。所有编辑操作在节点内部完成。

## 2. 绝对不能改的边界

这是本次改造的硬约束。违反其中任何一条都算改造失败，哪怕界面做得再好看。

### 2.1 不许碰的代码

| 路径 | 说明 |
|------|------|
| `packages/region-split/**` | 整个服务端与核心逻辑，**一行都不要动** |
| `apps/region-split-ui/src/state.ts` | store 的**公开接口**不得增删改。内部可以加私有辅助，但已有的状态、计算属性、动作的名字与语义必须原样保留 |
| `apps/region-split-ui/src/api.ts` | REST 客户端 |
| `apps/region-split-ui/src/coords.ts` | 坐标换算纯函数（见 §4，新界面复用它，不要重写） |

可以自由改写的只有：`App.vue`、`components/**`、新增的画布相关模块、样式。

### 2.2 store 的公开接口（新界面必须原样消费）

**状态**：`projectId` `doc` `regions` `selectedIds` `mode` `busy` `busyLabel` `error` `pendingRenameIds` `renamingId` `modelConfig`

**计算属性**：`selectedIndex` `selectedRegion` `canNudge` `canMerge` `canUndo` `canRedo` `isModelConfigured` `candidateLines` `needsAnalysis`

**动作**：`uploadImage` `load` `analyze` `select` `clearSelection` `nudge` `beginSplit` `cancelSplit` `commitSplit` `merge` `rename` `startRename` `stopRename` `aiRename` `undo` `redo` `flushPersist` `loadModelConfig`

新界面就是这些东西的另一种画法。**任何"新界面需要 store 加个新动作"的念头，先停下来想想是不是画法没选对**——如果确实需要，那也只能是纯展示用的派生状态，不能是新的数据变更路径。

### 2.3 必须存活的行为

改完之后，下面每一条都要照旧成立。这些是过去踩坑换来的，不是可有可无的细节：

1. **区域不变量**：升序、首尾相接、覆盖全图、每块 ≥8px、`id` 唯一。服务端会拒绝违反的写入，界面不该产生这种请求。
2. **撤销/重做**：`Ctrl+Z` / `Ctrl+Shift+Z`；连续微调按 500ms 合并成一步。
3. **进行中锁定**：上传/载入/分析期间显示遮罩，画布与列表不可编辑。store 里的守卫是真防线，遮罩只是视觉层——两者都要保留。
4. **拆分吸附**：拆分线靠近候选切分线时吸附，靠近区域上下边缘 8px 内变红且点击无效。
5. **未分析提示**：`needsAnalysis` 为真时必须有醒目提示，说明当前是初始划分而非 AI 结果。这个提示解决过真实的误解，不能因为"影响美观"去掉。
6. **自动重命名占位**：`pendingRenameIds` 里的区域显示"命名中…"。
7. **键盘**：只有 `↑↓` 微调、`Ctrl+Z`/`Ctrl+Shift+Z` 撤销重做、`Esc` 退出拆分模式/清空选中。输入框聚焦时全部不响应。
8. **模型未配置**：分析与 AI 重命名禁用，并提示去编辑哪个配置文件（路径来自 `modelConfig.configPath`）。

### 2.4 测试

`apps/region-split-ui` 现有测试（84 个）中，针对 `state.ts` 和 `coords.ts` 的**必须一个不改地继续通过**——它们测的是功能，不是界面。

针对组件的测试（`ImageCanvas.test.ts` 等）可以随组件重写，但**每一条被删掉的断言都要在新测试里有对应**。特别是这几条，它们各自对应一个真实修过的 bug，不许丢：

- `canUndo`/`canRedo` 的响应性（曾因 computed 无响应式依赖导致按钮永不亮起）
- 进行中时所有变更动作是空操作
- 拆分线的吸附与非法位置判定
- 未分析提示的显示与消失

## 3. 为什么是"流水线节点图"而不是"区域节点图"

实现前先理解这个决定，否则很容易做成一堆无意义的连线。

**区域之间不该连线。** 区域是一维垂直堆叠、首尾相接的，相邻关系已经由它们在图上的位置完整表达了。再画一条线从"区域 3"连到"区域 4"，不传递任何新信息，纯装饰。

**流水线之间该连线。** 数据确实在这几步之间流动，而且每步的产物不同：

```
图片源 ──▶ 表面分析 ──▶ AI 分段 ──▶ 区域文档
 原图      候选线+面板    语义分段     最终区域
```

把它画成节点图有实际价值：用户能一眼看出**当前数据走到哪一步了**。这个工具此前最大的认知障碍就是"初始划分"和"AI 结果"长得一模一样，节点图天然把这件事说清楚——AI 分段节点没亮，就是没跑过。

## 4. 坐标系（最高风险项，先读这节）

现在是两层坐标：**原图像素**（`bounds` 存的）↔ **屏幕像素**。换算在 `coords.ts`：

```ts
toImageY(clientY, rectTop, displayScale) => Math.round((clientY - rectTop) / displayScale)
```

加了无限画布之后会变成三层：原图像素 ↔ 画布坐标 ↔ 屏幕像素。**三层换算是这次改造最容易出错的地方**，区域选中、拆分线跟随、吸附全都依赖它。

### 强烈建议：让图片节点按 1 图片像素 = 1 画布单位渲染

这样画布坐标在图片节点内部**就是原图像素**（只差一个节点位移），三层塌缩回两层，缩放交给画布的 `zoom` 承担。于是：

```
原图 y = (屏幕 y − 图片节点在屏幕上的顶边) / zoom
```

这正是现有 `toImageY(clientY, rectTop, displayScale)` 的形状——**把 `rectTop` 传成图片节点的屏幕顶边、`displayScale` 传成 `zoom` 即可，`coords.ts` 一行都不用改**。

不要另起一套换算写在组件里。所有屏幕↔原图的转换都必须走 `coords.ts`，新增的换算也加在那里并补纯函数测试。

### 已知的测试约定

现有组件测试跑在 jsdom 里，`getBoundingClientRect()` 全返回 0、`clientWidth` 为 0。现有 `ImageCanvas` 因此把 `displayScale` 兜底成 1，让测试里的坐标是 1:1。**新画布必须保留同样的兜底**（zoom 未初始化时视为 1），否则组件测试没法写。

## 5. 节点设计

四个节点，固定拓扑，**用户不能新增/删除节点或改连线**——这是流水线的可视化，不是编辑器。节点位置可拖动，位置存 `localStorage`（纯视图状态，不入区域文档）。

### 5.1 图片源

- 缩略图、文件名、`1170 × 2532`
- 预处理结果：`已抹除 顶部 101px · 底部 41px`，hover 说明这是手机状态栏与 Home Indicator
- 未上传时整个节点是拖放区 + "选择图片"按钮
- 端口：输出 ×1

### 5.2 表面分析

- `候选切分线 12 条` `卡片面板 7 块`
- 两个开关，控制这两样是否叠加显示在区域画布上（默认候选线关、面板关）
- 这一步不需要模型，**未配置模型时也是亮的**——文案要体现这点
- 端口：输入 ×1，输出 ×1

### 5.3 AI 分段

- 模型名（来自 `modelConfig.model`）；未配置时显示警告与配置文件路径
- `[重新分析]` 按钮（点击前二次确认，沿用现有文案）
- 状态：未运行 / 运行中（进度动画）/ 已完成（显示 `analyzedAt`）
- **`needsAnalysis` 为真时这个节点要有明显的"未运行"视觉**——这是 §2.3 第 5 条那个提示的主要载体
- 端口：输入 ×1，输出 ×1

### 5.4 区域文档（主节点）

体积最大，是实际干活的地方。内部两栏：

- **左**：清理后的图 + 分段色块叠加 + 选中高亮 + 拆分线
- **右**：区域列表（序号、名称、类型、置信度、滚动徽章 `↔`/`↕`）

上方是上下文操作条（沿用现有逻辑：单选显示微调/拆分/重命名/AI 重命名，多选显示合并）。

端口：输入 ×1。

## 6. 连线

- 贝塞尔曲线，从上游节点的输出端口到下游的输入端口
- **有数据流过**：亮色（`--edge-active`），可选流动动画
- **上游未就绪**：暗色虚线（`--edge-idle`）。例如没上传图片时全部是暗的；没跑过分析时"AI 分段 → 区域文档"这条是暗的
- 连线不可交互——不能拖拽、不能断开、不能新建

## 7. 深色主题

先定 token 再写组件，不要散落硬编码色值。

```css
:root {
  --bg-canvas:      #16181d;   /* 画布底 */
  --bg-node:        #24272e;   /* 节点体 */
  --bg-node-header: #2c3038;
  --bg-inset:       #1c1f25;   /* 节点内的图片区/列表区 */
  --border:         #383d47;
  --border-strong:  #4a505c;

  --text:           #e6e8ec;
  --text-dim:       #9aa1ad;
  --text-faint:     #6b7280;

  --accent:         #4c8dff;   /* 选中、主按钮、活跃连线 */
  --accent-soft:    #4c8dff22;
  --warn:           #e2a400;   /* 未配置模型、未分析 */
  --danger:         #ef5f5f;   /* 错误、非法拆分位置 */
  --ok:             #3ecf8e;

  --edge-active:    #4c8dff;
  --edge-idle:      #454b57;
}
```

画布背景加点阵网格（ComfyUI 那种），网格随 zoom 缩放。

**区域色块的配色要重挑**。现在用的是浅色底上的 `#00000008`/`#00000014` 交替，在深色背景上完全看不见。深色下建议用低透明度的冷色交替 + 选中时 `--accent` 描边。**分段色块必须始终能看清边界**，这是这个工具的核心信息。

## 8. 交互规范

事件归属要划清楚，否则会互相打架：

| 操作 | 归属 |
|------|------|
| 空白画布拖拽 | 平移画布 |
| 滚轮 | 以光标为中心缩放（限制 0.2×–3×） |
| 节点标题栏拖拽 | 移动节点 |
| 节点内部一切 | 节点自己的交互，**必须 `stopPropagation`**，不能触发画布平移 |
| 区域色块点击 | 选中（`Ctrl`/`Shift` 加选） |
| 拆分模式下画布区 | 跟随鼠标画线，点击提交 |

补充：

- 画布右下角放缩放控件（`+` / `−` / `适应窗口`）
- `适应窗口` 把整个流水线缩放到可见范围
- 首次打开自动执行一次"适应窗口"
- 进行中遮罩盖住整个画布（现在的实现是盖内容区，改造后语义相同）

## 9. 技术选型

**推荐 `@vue-flow/core`**（Vue 3 原生、MIT）。它把平移缩放、节点拖拽、贝塞尔连线、选中这些琐碎的部分都做完了，`useVueFlow().screenToFlowCoordinate()` 正好提供 §4 需要的换算原语。

风险点只有一个：**区域画布是自定义节点，内部有自己的鼠标交互**，要确保节点内部事件不冒泡到画布。Vue Flow 支持自定义节点内容，处理好 `stopPropagation` 即可。

也可以手写——本图拓扑固定、连线不可交互，平移缩放约百行、贝塞尔连线约五十行。手写的好处是坐标系完全自己掌控，不必反推库的变换管线。**两种都可以，选定后在实现说明里写清理由。**

不要引入整套 UI 组件库，现有界面的控件很少，自己写更可控也更贴合深色主题。

## 11. 实施顺序

每步做完都应该是能跑的，不要憋大招。

1. **主题 token + 深色皮肤**，界面结构不动。这一步就能验证配色是否可读，尤其是分段色块。
2. **画布容器**：平移、缩放、网格、适应窗口。先放一个占位节点。
3. **区域文档节点**：把现有的图 + 列表 + 操作条搬进节点。**这步做完功能就应该完整可用了**，后面都是锦上添花。
4. **其余三个节点 + 连线**。
5. **节点位置持久化、缩放控件、细节打磨**。

## 12. 验收标准

1. `pnpm -C ui test` 全绿；`state.ts` 与 `coords.ts` 的测试**一行未改**。
2. `pnpm -C ui -r typecheck` 与 `pnpm -C ui/apps/region-split-ui build` 通过。
3. `packages/region-split/**` 的 `git diff` 为空。
4. §2.3 的八条行为逐条手工验证通过。
5. 真实浏览器里走通：上传 → 分析 → 微调边界 → 拆分 → 合并 → 重命名 → 撤销重做，全程无坐标偏移（点哪选中哪、拆分线跟手）。
6. 缩放到 0.2× 和 3× 时，区域选中与拆分线位置仍然准确——**这是坐标系是否做对的判据**。

## 13. 明确不做

- 节点的新增/删除/自定义连线（这是流水线可视化，不是节点编辑器）
- 区域之间连线（§3 已说明为何无意义）
- 多图/多项目的画布管理
- 任何服务端改动
- 任何 store 公开接口的改动
