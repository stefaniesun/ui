# 区域内元素组件拆分设计

## 1. 背景与目标

现有系统先把 UI 效果图拆成连续、全宽的纵向区域，并允许用户调整区域边界、拆分、合并和重命名。区域模型只能描述页面的大模块，不能表达区域内部的文字、图片、按钮、输入框和容器等二维元素。

本功能在不破坏现有区域不变量和双图工作区的前提下，为每个区域增加自动元素识别和完整人工校正能力：

- 区域 AI 分析成功后，自动分析各区域内部元素。
- 元素使用二维矩形框表示，并支持父子树。
- 支持选择、添加、移动、缩放、删除、重命名、修改类型和调整父级。
- 区域边界变化后自动更新元素归属，跨界元素保留并标记冲突。
- 元素编辑接入现有撤销、重做和防抖持久化机制。
- 单个区域分析失败时允许局部重试，不阻断已成功区域的使用。

非目标：

- 不在本阶段生成 Vue 组件源码。
- 不改变区域必须覆盖整张图片、连续且全宽的结构。
- 不使用纯前端视觉算法替代模型语义识别。

## 2. 总体方案

采用“两阶段分析”方案：

1. 沿用现有整图区域分析，产生稳定的纵向区域。
2. 区域分析完成后，以清理后的原分辨率图片为来源，按区域裁图，并行调用模型识别每个区域的元素。

选择该方案而不是让模型一次返回区域和元素，是因为区域裁图上下文更集中、坐标更准确，单个区域失败可独立重试，且能最小化对现有区域分析链路的修改。元素分析最多同时执行 3 个请求，避免模型服务过载。

## 3. 数据模型

### 3.1 元素类型

新增固定元素类型枚举：

- `container`
- `text`
- `image`
- `icon`
- `button`
- `input`
- `textarea`
- `select`
- `checkbox`
- `radio`
- `link`
- `list`
- `list-item`
- `divider`
- `other`

### 3.2 ElementNode

在核心包中新增 `ElementNode`：

- `id: string`：文档内唯一 ID。
- `regionId: string`：所属区域 ID。
- `parentId: string | null`：父元素 ID；`null` 表示区域直属元素。
- `displayName: string`：用户可编辑名称。
- `type: ElementType`：固定枚举中的元素类型。
- `bounds: Rect`：原图绝对坐标，整数像素。
- `confidence: number`：模型识别置信度，仅用于数据和诊断，不作为主界面百分比展示。
- `conflict: boolean`：元素是否跨越区域边界或违反当前归属约束。
- `source: "ai" | "manual"`：来源。

`RegionSplitDoc` 增加：

- `revision: number`，旧文档默认 `0`；每次成功写入递增，用于乐观并发控制。
- `elements: ElementNode[]`，旧文档默认 `[]`。
- `elementAnalysis: Record<string, RegionElementAnalysis>`，旧文档默认 `{}`。

区域 `id` 是持久身份，一旦创建不得因重命名而变化。AI 重命名只更新 `displayName`、`type`、`scrollX`、`scrollY`；服务端忽略模型返回的语义 ID。拆分可以创建新 ID，合并保留首区域 ID。

`RegionElementAnalysis` 保存区域级分析状态：

- `status: "pending" | "analyzing" | "ready" | "stale" | "failed"`
- `error?: string`
- `analyzedAt?: string`
- `inputFingerprint?: string`：由区域边界、名称、类型和裁图版本形成，用于拒绝过期分析结果。

分析中的瞬时状态主要由服务端流程和前端本地状态驱动；落盘状态用于重新载入项目后恢复局部失败与成功信息。写入文档时不得长期保留无对应执行任务的 `analyzing`，服务启动或文档读取时将残留的 `analyzing` 归一化为 `failed`。区域边界、名称或类型改变后，对应状态转为 `stale`；拆分后的两个区域均为 `pending`，合并结果为 `pending`，已删除区域的状态键必须移除。

### 3.3 坐标约定

- 文档中的区域和元素统一使用原图绝对坐标。
- 模型返回区域裁图内的整数相对坐标。
- 服务端按区域的 `bounds.x`、`bounds.y` 转换为原图绝对坐标。
- 前端只在渲染和指针交互边界做显示坐标与原图坐标换算。
- 元素最小宽高均为 `4px`。

## 4. 模型接口与分析流程

### 4.1 模型响应

扩展现有模型抽象，新增 `analyzeElements` 能力。输入包括：

- 区域裁图的 Base64 数据。
- 裁图宽高。
- 区域名称和区域类型，作为语义上下文。

模型返回扁平元素数组，每项包含临时 ID、父临时 ID、名称、类型、相对矩形和置信度。使用扁平结构比递归 JSON 更易做模式校验和错误定位。

服务端执行以下校验和标准化：

1. 响应必须满足严格 schema。
2. 坐标四舍五入为整数，并裁剪到区域裁图范围；裁剪后小于 `4px` 的元素丢弃。
3. 元素 ID 必须唯一；父 ID 必须指向同一响应中的元素。
4. 父子关系不得成环。
5. 子元素必须完整落入父元素；不满足的模型项不进入最终结果。
6. 将临时 ID 替换为稳定文档 ID，并把相对坐标转换为原图绝对坐标。
7. AI 结果初始 `source` 为 `ai`、`conflict` 为 `false`。

### 4.2 自动分析

`analyzeProject` 完成区域分析后，继续运行元素分析。首次分析与整图“重新分析”都视为一次完整替换：新区域和新元素作为单个服务端结果提交，不把旧元素混入新区域 ID 空间。前端在重新分析前明确提示会替换区域和元素人工编辑；旧状态只保留在本地撤销快照中。

1. 为全部新区域建立 `pending` 状态。
2. 使用最多 3 个并发任务，从清理后的原分辨率图片裁剪区域。
3. 每个任务独立调用模型、校验结果并形成区域元素快照。
4. 成功区域写入新元素并标记 `ready`。
5. 失败区域不继承旧区域元素，保持空元素并标记 `failed`，记录经过清理的错误消息。
6. 全部任务结束后，在项目写锁内校验基准版本并原子提交完整新文档。

只要区域分析成功，接口就返回并落盘区域结果；部分或全部元素分析失败都通过 `elementAnalysis` 表达，不将整个 HTTP 请求改成失败，避免出现“服务端已写成功但前端按失败回滚”的歧义。全部元素分析失败时，前端根据返回状态显示应用内错误对话框，同时保留已落盘的区域结果。区域分析本身失败时不启动元素分析，也不替换旧文档。

### 4.3 局部重试

新增区域元素重试接口。调用前先保存前端待提交编辑；服务端只裁剪并分析指定区域。新结果只有在完整校验通过后才原子替换该区域现有元素，避免请求期间清空界面。区域处于 `stale` 时允许重试；请求携带当前 `revision` 与 `inputFingerprint`，完成时任一值变化都拒绝覆盖，并要求用户基于最新区域再次重试。

为避免并发写同一磁盘文档发生覆盖：所有修改文档的服务端入口都经过按项目串行的写协调器；自动分析中的区域任务只并发计算结果，由单一协调者汇总后写文档。统一编辑、整图分析、单区域重试都提交 `expectedRevision`，版本不匹配返回 `409` 和最新文档，不执行写入。服务端使用临时文件加原子替换落盘，最后再更新内存态。

## 5. 核心元素操作与不变量

核心包新增纯函数操作：

- 添加元素。
- 移动元素子树。
- 缩放元素。
- 删除元素子树。
- 重命名元素。
- 修改元素类型。
- 调整父级。
- 根据最新区域重新归属并标记冲突。
- 校验元素不变量。

操作规则：

- 元素框不得超出图片。
- 非冲突的顶级元素必须完整位于其 `regionId` 对应区域。
- 子元素必须完整位于父元素。
- 同一元素只能有一个父级。
- 父子关系不得形成循环。
- 删除父元素时删除完整子树。
- 拖动父元素时整棵子树使用相同位移，任一后代越出图片或所属区域时拒绝操作。
- 子元素移动或缩放后不能超出父元素。
- 父元素缩小后若不能容纳全部子元素，则拒绝操作。
- 调整父级时，新父元素必须与目标元素属于同一区域并完整包含目标元素。

## 6. 区域结构变化与元素联动

区域边界调整、拆分、合并后，调用统一的元素协调函数。现有拆分操作会直接修改原区域边界并创建新区域，合并操作会重建边界；实现时必须移除操作函数内的旧区域专用撤销假设，由 store 在操作前后记录完整编辑快照，避免双重入栈：

1. 只对顶级元素按绝对矩形重新判断区域归属。
2. 完整落入某一区域时更新其 `regionId`，并递归同步整个子树的 `regionId`。
3. 与一个或多个区域边界相交时保留当前归属并设置 `conflict: true`。
4. 冲突解决后重新计算并清除 `conflict`。
5. 子元素不独立跨区域迁移，其归属始终跟随顶级祖先。
6. 区域拆分和合并产生的新区域 ID 会通过相同算法修复元素 `regionId`，不留下悬空引用。

冲突不阻止区域继续编辑和文档保存。用户可以移动或缩放元素解决冲突，也可以重新分析对应区域。区域结构变更和由此产生的元素归属、冲突变化必须作为同一撤销步骤保存。

## 7. 前端状态与持久化

前端 store 增加：

- `elements` 响应式集合。
- `selectedElementId`。
- 元素编辑模式和当前手势状态。
- 区域级元素分析状态。
- 元素操作及局部重试动作。

现有撤销栈从仅保存 `Region[]` 扩展为完整编辑快照，包含：

- `regions`
- `elements`
- `elementAnalysis`
- 当前区域与元素选择

区域操作和元素操作共享同一撤销、重做顺序。拖动或缩放从 `pointerdown` 到 `pointerup` 合并为一条撤销记录；手势期间暂停持久化，结束后执行一次 `400ms` 防抖保存。`pointercancel`、失去捕获和组件卸载都必须结束手势并清理监听器。

持久化接口从只提交区域扩展为提交文档的可编辑部分，包含 `expectedRevision`、`regions`、`elements` 和 `elementAnalysis`。服务端统一校验区域和元素不变量后原子写入，避免两个独立请求互相覆盖。为兼容迁移，可保留旧区域接口，但新前端只使用统一编辑接口。收到 `409` 时，如果本地没有未提交修改则采用服务端最新文档；如果仍有本地修改则保留本地状态、暂停自动保存并显示冲突对话框，禁止静默覆盖任一版本。

## 8. 编辑界面

### 8.1 双图画布

保持原图和区域分析图左右紧贴、等尺寸：

- 原图只用于对照，不绘制元素框。
- 分析图继续显示区域覆盖层和分割引导。
- 元素框叠加在区域覆盖层之上。
- 选中元素显示名称标签和四角缩放柄。
- 冲突元素使用橙色边框和明确提示。
- 点击元素框与右侧树节点同步选择。
- 点击画布空白处清除元素选择，再按现有规则处理区域选择。

交互模式：

- 默认“选择”模式：点击选择，拖动框体移动，拖动四角缩放。
- “添加元素框”模式：在分析图空白位置拖拽创建，创建后立即选中并进入属性编辑。
- 区域拆分模式与元素添加/拖动模式互斥。
- 分析未完成、全局 busy 或区域元素仍在分析时，对应元素编辑入口禁用。

### 8.2 区域与元素树

右侧列表扩展为树形结构：

- 第一层仍是区域行，保留区域编号、名称、类型、滚动标识和上下边界按钮。
- 区域下显示顶级元素，子元素按父子关系递归缩进。
- 区域行显示元素数量、分析中、失败或冲突数量。
- 点击节点与画布同步选择和滚动定位。
- 元素支持双击重命名、类型选择、删除和调整父级。
- 失败区域显示“重新分析元素”操作；请求期间保留旧元素。

属性编辑区显示名称、类型、父级和 `x/y/w/h`。所有字段提交前执行同一核心校验。

### 8.3 键盘和可访问性

- `Delete` 删除选中元素及其子树。
- `Escape` 取消添加或当前手势。
- `Ctrl+Z` 撤销，`Ctrl+Shift+Z` 重做。
- 元素框和树节点具有可识别的 `aria-label` 和选中状态。
- 缩放柄提供足够点击区域，视觉尺寸可以小于实际命中区域。
- 输入框获得焦点时，全局删除和撤销快捷键不抢占文本编辑。

## 9. 错误处理

- 单个区域元素分析失败：在区域行显示非阻断错误和重试按钮，其他区域继续使用。
- 全部区域元素分析失败：显示应用内错误对话框；保留已落盘的新区域结果，失败区域的元素为空。旧区域和旧元素只存在于前端完整撤销快照中，可由用户撤销整图重新分析恢复。
- 模型返回非法结构：按区域失败处理，不将部分非法结果写入文档。
- 持久化失败：沿用现有错误展示与服务端状态回读策略；回读失败时保留本地编辑，避免半失败回滚覆盖用户操作。
- 局部重试失败：保留旧元素，不清空画布。
- 错误消息不得包含服务端绝对路径、模型密钥或原始敏感响应。

## 10. 测试策略

### 10.1 核心包

- 元素 schema、旧文档默认值和类型枚举。
- 模型响应解析、坐标转换、越界裁剪与过小元素拒绝。
- 重复 ID、无效父级、循环和子元素越界拒绝。
- 添加、移动、缩放、删除子树、重命名、改类型和调整父级。
- 区域边界变化后的自动归属、子树同步和冲突标记。
- 拆分、合并后不出现无效 `regionId`。
- 元素不变量检查。

### 10.2 服务端

- 自动元素分析在区域分析之后执行。
- 并发上限为 3。
- 成功结果汇总后单次写文档，不发生并发覆盖。
- 局部失败、全部失败和单区域重试。
- 重试成功前保留旧元素。
- 统一编辑接口的 schema 和不变量错误映射为 `422`。
- 老项目加载时 `elements` 和 `elementAnalysis` 正确补默认值。

### 10.3 前端 store

- 元素选择和区域选择互斥规则。
- 元素编辑及区域联动进入同一撤销栈。
- 拖动、缩放手势合并为一条撤销记录。
- 手势期间不保存，松开后只保存一次。
- 取消手势、卸载和持久化失败路径。
- 局部分析状态与重试。

### 10.4 Vue 组件

- 分析图显示元素框，原图不显示。
- 树与画布同步选择、悬停和定位。
- 添加、拖动、缩放、删除、重命名、改类型和调整父级交互。
- 父子约束、图片边界和最小尺寸。
- 冲突样式和区域状态提示。
- 分析未就绪、busy、拆分模式下的编辑门禁。
- 键盘事件、输入焦点保护、指针取消和监听器清理。

## 11. 实施边界与迁移

- `schemaVersion` 升级，并通过 Zod 默认值继续读取旧文档。
- 不迁移旧项目的元素数据；首次重新分析或手动重试时生成。
- 实施按核心模型与操作、模型分析与服务端、前端状态、画布编辑器、树形列表的顺序推进，每一步先补失败测试。
- 继续遵守项目本地依赖约束：第三方依赖与 pnpm store 均位于 `D:/workspace/ui` 内。本功能优先使用现有 Vue、Zod、Sharp 和浏览器 Pointer Events，不新增拖拽框选第三方库。
