# 整页生成与资产落地设计

2026-08-18

交付物从"按区域生成的片段"改为**整页生成**;区域分析阶段负责把生成器需要的属性与资产**落地成数据**,不留到生成时现找。

本文是**设计**,不是实施计划。第 9 节给出子项目划分,每个子项目单独出计划。

> **写给接手的人:** 上一次有人拿着一份 3898 行的大计划一次性实现,产出的界面"完全是混乱的"。事后归因是计划太大、UI 任务排在最后、UI 代码从没真正渲染过。**请按第 9 节逐个子项目做,每个都以"在真浏览器里看一眼"收尾。**

---

## 1. 结论:交付物是整页,按区域降级为诊断探针

现状是每个区域各生成一份 `index.html` + `style.css`。这条路走不通,有一个现在就能验证的硬理由,和一批结构性的理由。

### 1.1 硬理由:类名是区域内唯一的,拼不起来

节点 id 由每棵树各自从 `n1` 开始编号,`classKey()` 只是把 id 转成合法类名、**不带区域信息**。实测基准项目:

```
共 20 个不同的节点 id，其中 18 个在多个区域里重复出现
  «n1» 出现在 11 个区域    «n2» 出现在 10 个区域
  «n3» 出现在 10 个区域    «n4» 出现在 10 个区域
```

把各区域的 CSS 拼在一起,`.e-n1` 会被定义 11 次、每次指向完全不同的元素。**这不是"稍微调调"的问题,是直接撞车。**

### 1.2 结构理由:有一批决定天生是页级的

这些量按区域各算一套等于没算:

| 决定 | 为什么必须页级 |
|---|---|
| 字号阶梯 | 每区域各一套阶梯,就回到了"47 个互不相同的小数" |
| 颜色阶梯 | 同上 |
| 间距阶梯 | 同上 |
| 字体栈 | 整页一个 |
| 跨区域的重复结构 | 同一个列表样式出现在多个区域,该出一个 class 而不是 N 个 |
| 类名分配 | 见 1.1 |

**按区域生成的产物,缺的不是"拼接"这一步,而是那些只有看到整页才做得出的决定。** 硬拼只会把错误固化。

### 1.3 但不要删掉按区域生成——它换个身份继续有用

| | 按区域 | 整页 |
|---|---|---|
| 身份 | **诊断探针** | **交付物** |
| 回答什么 | 这个区域的数据准不准 | 还原度几成 |
| 何时用 | 解析完一个区域立刻看 | 全部解析完之后 |
| 产物形态 | 自包含(资产内联),方便单独打开 | 文件分离,`index.html` + `style.css` + `assets/` |

按区域那个的价值恰恰是**不用等全页**——调完一个区域马上看到布局对不对。它现在做的就是这件事,只是不该被当成交付路径。

## 2. 分层:什么在区域分析阶段产出,什么必须留到整页

这是本文最要紧的一张表。判据只有一条:**这个量只用得到本区域的信息,还是必须看到全页?**

### 2.1 区域分析阶段产出(逐元素,存进元素树)

| 属性 | 现状 | 说明 |
|---|---|---|
| `box` / 父子 / `layout` / `repeat`(含 `slot`) | ✅ 已有 | |
| `kind` / `displayName` | ✅ 已有 | 模型定 |
| `style.background` / `color` / `borderRadius` | ✅ 已有 | |
| `textBox` 校验 | ✅ 已有 | |
| **`style.fontSize` / `fontWeight`** | ⚠️ 只在人工点"测量"时才有 | 改为**检测时自动测**,存**原始拟合值**(连续小数) |
| **文字字面量** | ❌ 缺 | 见第 4 节 |
| **图片 / 图标资产引用** | ⚠️ 生成时现切,没存 | 见第 3 节 |
| **图标库名** | ❌ 缺 | 见第 5 节 |

### 2.2 必须留到整页阶段

| 处理 | 为什么 |
|---|---|
| 字号 / 颜色 / 间距的**量化** | 阶梯是全页共享的 |
| **类名分配** | 要保证全页唯一 |
| **区域堆叠成页** | 按 `regions.json` 的 y 排序 |
| **跨区域的样式合并** | 同构结构复用同一个 class |
| **字体栈选择** | 项目级一次决定 |

**关键取舍:区域阶段存的是"原始测量值",整页阶段做的是"归拢"。** 在区域阶段就把字号定死,等于每个区域各有一套阶梯——正是量化要消灭的东西。

## 3. 资产:切图不能当成"存一次就完事"

### 3.1 现状

服务端的 `/api/projects/:id/code` 路由**已经在生成时按框现切**,内联成 data URL 塞进 `assetSources` 交给 `emitHtml`。这条路的优点是**天生不会过期**——每次都按当前的框重切。

### 3.2 为什么还要改

两个原因:

1. **整页交付要文件不要内联。** 一页几十张图内联成 base64,体积膨胀约 1/3;而设计文档里早就记着小程序主包 2MB 的限制。交付物应该是 `index.html` + `style.css` + `assets/`。
2. **重复切图浪费。** 同一张图在多次生成、多个区域里被反复裁剪编码。

### 3.3 但"在分析时切一次存下来"会引入过期的谎

资产是从 `box` 裁出来的,而**框会被人工微调**。解析完切了一张,然后调了框,磁盘上那张就过期了——**而且过期得看不出来**:生成的页面里图还在,只是错位或裁多裁少。

这和 `textBox` 那个教训是同一类:**一个陈述句式的字段,在它依赖的东西变了之后不更新,就变成了谎。**

### 3.4 方案:按几何寻址的缓存

```
data/projects/<id>/assets/<sha1(projectId + box.x,y,w,h)>.png
```

- 节点上存 `asset: { ref: string; cutFrom: { x, y, w, h } }`
- 取资产时比对 `cutFrom` 与当前 `box`:**对不上就重切并更新引用**
- 键里含几何,所以**同框必同文件**——去重是免费的
- 缓存目录可以随时整个删掉重建,不是真相源

这样"存起来"与"永不过期"同时成立:文件是持久的,但**它是派生物,不是真相**。真相永远是原图加框。

### 3.5 纯色块不切图

已有的结论:`icon` 框里只有一种颜色的,不是图标是纯色块,降级成 `decoration` 用 CSS 背景色表达。**这类节点不产出资产。**

## 4. 文字内容:生成器需要,IR 里没有

`text` 节点现在只有 `displayName`——那是模型给的**名字**,不是**字面量**。名字碰巧等于内容的只是这类短标签;标题类会变成"活动标题"这种。**生成出来的页面里文字是节点名。**

这和图片资产是同一个性质的缺口:生成器需要、IR 里没有。

**方案:复用现有的模型调用。** 叶子分类那次调用已经在看裁图了,顺手多要一个 `text` 字段几乎零成本;认短文字是视觉模型擅长的,不违背"模型只做判断"的分工。

存成 `style.text?: string`(或顶层 `text`,实施时定)。**没有这个字段时退回用 `displayName` 并在生成的 HTML 上打 `data-todo="text"`**,与现状一致。

> OCR 作为交叉校验是独立子项目,不在本文范围。

---

## 5. 图标:存名字不存文件

已有的结论(见 `2026-08-17-codegen-and-fidelity-design.md` 第 4 节):

```
模型看图 → 输出英文关键词 → 代码在本地图标索引里检索 → 人工从候选里挑 → 存名字
```

存 `style.icon: { source, name, keywords, by }`,**不存 SVG 内容**——SVG 在生成时按名字现取,换图标风格不用动已有解析结果。

**切图退成兜底**:图片必须切;图标库找不到时也要有退路。所以第 3 节那套缓存对 icon 同样适用,只是优先级低于图标名。

## 6. 整页生成器的形态

### 6.1 输入

```ts
emitPage({
  designWidth: number;          // 原图宽度
  regions: { region: Rect; tree: ElementTree }[];   // 按 y 排序
  assets: (nodeKey: string) => string | undefined;  // 资产引用解析
})
```

### 6.2 类名分配

全页唯一。建议 `e-{regionIndex}-{nodeId}`,或整页重新编号。**必须有测试钉住"两个区域里的 n1 不会撞车"**——这是 1.1 节那个 bug 的回归测试。

### 6.3 区域堆叠

按 `regions.json` 的 y 排序,每区域一个 `<section>`,高度取 `region.h`,背景取 `tree.background`。区域之间通常无缝(区域是连续切分出来的),但**不要假设**——按实际 y 值定位。

### 6.4 沿用现有的所有规则

这些已经实现并有测试,整页生成器**必须继续遵守**:

- **单位只用比例**,Web 落 `vw`;纵向也用 `vw` 不用 `vh`
- **跨端安全子集**:只用 `div` / `span` / `img`,布局只用 flex 与 absolute
- **重复组按 `pitch` 出等宽格子**,交叉轴用 `slot`,不用 `gap`
- **flex 复现不了就退回绝对定位**,并把偏差写进 CSS 注释
- **列表项不各自写宽高**,由 `> *` 一条规则给;**不许用 `!important`**
- **输出顺序必须父先子后**(拓扑排序),`> *` 靠"后写的赢"压过列表项自己的规则
- **绝对定位的角标**不参与槽位,保留自己的实测尺寸

## 7. schema 变更汇总

```ts
// 节点上新增
asset?: {
  /** 缓存文件名，按几何寻址 */
  ref: string;
  /** 这张是按哪个框切的。与当前 box 对不上就要重切。 */
  cutFrom: { x: number; y: number; w: number; h: number };
};

// style 上新增
text?: string;                    // 文字字面量（第 4 节）
icon?: {                          // 图标库引用（第 5 节）
  source: "iconify";
  name: string;
  keywords: string[];
  by: "model" | "human";
};
```

全部**可选**——已存盘的文件没有这些字段,读出来必须不炸。这一条在 `textBox` 和 `repeat.slot` 上已经踩实过两次。

## 8. 已知会踩的坑(前面已经踩过,别再踩)

1. **改了核心包必须重启 API**,tsx 不热重载。这条在本项目里已经吃过三次亏,最近一次是走查时第一次 detect 返回的 `repeat` 没有 `slot`。
2. **改共享类型时两个包的 typecheck 都要跑。** 有一轮只验了核心包,前端 typecheck 红了没人发现。
3. **在仓库根目录跑 `pnpm test` 会有 4 个失败**,包目录里跑是绿的——`element-text-box.test.ts` 用相对路径读基准图。这是既有问题,别被误导。
4. **测试要验"拿掉修复会不会变红"。** 本项目出现过多次假绿,最近一次是"断言 style 变了"被无关的重渲染满足。
5. **纯判据不要靠挂整个组件去测。** 画布的平移判据挂着组件测时跟异步视口重定位打架,挪成纯函数后 7 条用例干净利落。

## 9. 子项目划分与顺序

**不要合并成一个大计划。** 每个子项目独立出计划、独立验收、独立以"在真浏览器里看一眼"收尾。

| 顺序 | 子项目 | 依赖 | 验收标准 |
|---|---|---|---|
| 1 | **资产缓存**(第 3 节) | 无 | 同一个框重复生成只切一次;改框后自动重切;缓存目录删掉能重建 |
| 2 | **文字字面量**(第 4 节) | 无 | 模型返回的 `text` 落进树;缺失时退回 `displayName` 并打 `data-todo` |
| 3 | **字号自动测量**(2.1) | 无 | 检测后每个通过校验的 `text` 节点都带 `fontSize`;未通过的不带 |
| 4 | **整页生成器**(第 6 节) | 1、2、3 | 两个区域里的 `n1` 不撞车;整页能在浏览器打开;沿用 6.4 全部规则 |
| 5 | **按区域降级为诊断**(1.3) | 4 | 区域产物自包含(资产内联);整页产物文件分离 |
| 6 | **整页叠加比对**(1.3) | 4 | 能拖滑块看整页错位 |
| 7 | **量化**(2.2) | 4 | 全页字号收敛到个位数档位;颜色、间距同理 |
| 8 | **图标库检索**(第 5 节) | 无 | 关键词检索出候选;人工可换;IR 存名字 |

**1、2、3 可以并行**,它们互不依赖且都是"往树里补数据"。4 必须等它们齐了。**7 排在 4 之后**——量化要用到整页视角,而整页生成器是它的载体。

## 10. 明确不做

- OCR 交叉校验(独立子项目)
- 小程序 / RN emitter(交付物形态由用户决定,见 `2026-08-17-codegen-and-fidelity-design.md` 第 1 节)
- 交互语义(按钮、跳转、状态)
- 自动像素 diff(叠加滑块已能定位问题)
- 字体族自动判别(已否定,见 `2026-08-17-codegen-and-fidelity-design.md` 第 3.4 节)

## 11. 遗留未定项

- 类名方案取 `e-{regionIndex}-{nodeId}` 还是整页重新编号,实施时定;**唯一性必须有测试**。
- 资产缓存的清理策略(何时删掉不再被引用的文件)未定。
- 文字字面量放 `style.text` 还是顶层 `text`,实施时定。
- 整页产物的目录结构(`assets/` 用相对路径还是 base64 内联的阈值)未定。
- 区域之间若有缝隙或重叠(区域边界被人工调过)如何处理,未定——现有数据里区域是连续的,但不该假设。
